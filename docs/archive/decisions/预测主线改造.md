# 预测主线改造决策与实现边界

> 历史资料：保留编写时的实现、计划及验收结论，不作为当前使用说明。当前入口见 [文档导航](../../README.md)。

日期：2026-10-27。设计版本 0.3。普通预测主线已实现；外部模型质量、真实服务全链路与真实前瞻效果仍待独立验收。

## 1. 问题与决策

旧流程要求用户定义目标、填写时间、摘录正文、审查相关性和结果集合，默认又仅输出无概率情景。它能记录分析过程，却没有要求明确交付有区分力的判断。固定两条检索、逐轮三个问题、单个当前状态引用的资格开关，也不足以承担自动预测任务。

采用以下决策：

1. 普通 `chat` 由应用服务组织读取、目标建议、研究、证据分析和预测；`chat --manual` 保留高级人工入口。复用原有研究、证据、评估、预测、冻结和核验服务。
2. Reader 仍只提取原文。目标与研究计划由单独的模型任务提出，系统假设、行动条件与原文事实分开保存。
3. 整个普通会话最多一轮、三个自动澄清问题。额度保存在会话，跨恢复、重新规划和用户补充不重置。跳过以明确未知保存。需要另一次独立探索可新建会话，原会话预算不重置。
4. 交付包含主判断或具体无法判断原因、参照、本次差异、关键驱动、未知影响和改变判断的条件。数值预测、方向判断、条件分析、开放探索和无法判断分别标识。
5. 主观数值资格基于结构化判断依据及其限制，不再由“有一条当前状态引用且无关键问题”决定。统计估计仍不得冒用；没有合格数据不虚构基础率。
6. 实时分析先采集，再固定证据截止。严格实验继续沿用预登记 Tc/T0，不因普通流程改变而放宽。

## 2. 已实现数据流

```text
Chat → AssistanceService
       → EventService / Reader：原文陈述
       → target-research-1.0：目标、结果定义、假设、最多4条查询
       → 一轮必要澄清（可跳过，程序保存额度）
       → ResearchService：首轮最多2条查询
       → evidence-reading-1.0：正文精确摘录、相关性、数值依据与缺口
       → 至多一次补充研究与重新阅读
       → 固定截止、新事件版本及原正文快照关联
       → AssessmentService：普通分析资格
       → ForecastService / forecast-2.0：有区分力的判断或明确限制
       → 原报告、导出、冻结与手动核验服务
```

初始研究计划最多四条查询，首轮最多两条；剩余查询用于证据分析发现的重要缺口。第二轮只能选择本次展示并授权的剩余查询，不能任意添加外发文本。每轮最多六页并受会话总页面/查询/时间配额约束。研究时间最多使用120秒且为阅读与预测保留至少120秒；余量不足时停止研究、保留限制。上述是初始工程默认，不是最优预测参数。

本段为原改造决策；后续新增查询授权和正文选择的当前行为见[研究质量优化](研究质量与预测评估优化.md)及详细设计第6节。

自动阅读每页最多4000字符、总计24000字符，裁剪明确记录；未提供给模型的部分不得作为已读分析依据。模型只返回精确原文，程序计算偏移、校验唯一出现与文档归属，再走既有 `EvidenceService.cite`。模型相关性分析不等于事实已核实，也不标成人工审查。

当前实现是有界的目标驱动查询与一次缺口反馈，不是无限网页浏览，也不声称自动识别所有高价值资料。复杂HTML、图表、动态网页仍受现有正文抓取能力限制。

## 3. 目标、澄清与行动条件

`AnalysisPlan` 保存一个主要目标、类型、期限、结果定义、核验来源、假设及 `baseline / conditional / exploration`。默认相对期限为30天；明确的绝对窗口必须保留，已经开始时拒绝作为事前预测，不静默移窗。

澄清候选必须说明 `changes_judgment` 与 `cannot_research_reason`。只询问目标含义或无法自行调查的私人事实。程序执行一轮总额、最多三个、已用额度后禁止模型再产生问题；模型负责判断语义必要性。该限制能防止循环，但不能证明首次问题一定必要，仍须语义抽查与真实用户验收。

用户提供实际答案或跳过目标澄清后重新读取原文与答案，拟定最终问题。研究后直接回车跳过私人问题，且来源、事件及研究版本均未变时，保存未知与判断影响并复用已有研究继续判断，详见[交互负担优化](减少预测交互负担.md)。仍无法定义目标时保存 `unanswerable` 及具体原因，不伪造确认或生成无意义的 Forecast。该情况可查看会话状态；现有报告文件导出面向已生成的 Forecast，不将目标未定义强制包装成报告。

普通模式不要求逐项人工确认，`EventRevision.semantic_review=system_reviewed` 明示系统整理；高级模式保留 `user_confirmed`。二者都不代表外部事实已被验证。

条件分析明确行动及适用前提；不得将各行动下的条件结果随意加权成总体概率，或以相关性声称干预改善。当前一次分析聚焦一个目标；多个指标应分别运行，不能强行组成互斥分类。

## 4. 判断契约与方法资格

新版 `ForecastSpec / ForecastDraft / Forecast` 使用 Schema 2.0，方法 `judgment-2.0`、提示词 `forecast-2.0`。`ForecastSpec.guidance` 保存目标、行动条件及默认；`ForecastDraft.judgment` 保存以下内容：

| 字段 | 约束 |
|---|---|
| delivery | probability / directional / conditional / exploration / unable |
| conclusion | 当前主判断，或具体无法判断原因 |
| primary_outcome / ranking | 概率及方向判断必须对应有效结果并提供完整排序；其他交付不声称总体排名 |
| reference_kind / reference_basis | 历史、参照群体、时间表、延续假设、主观判断或确实缺失 |
| differences_and_adjustment | 当前事件与参照的差异及调整理由；不凭空制造概率增量 |
| key_drivers | 1–5项与结果有关的因素；按需分析约束、反馈和滞后 |
| unknown_effects | 未知如何影响结论 |
| change_conditions | 可观察的改判条件 |
| no_numeric_reason | 无概率时必须解释 |

程序检查输出版本、结果对应、完整排序、概率与排序一致、概率范围及总和、引用集合和交付类型。定性排名不换算百分比。条件分析、探索和无法判断可以完成执行，但不计作数值预测成功。报告从保存对象渲染，不自行补结论。

自动评估使用 `evidence-assessor-2.0`，保存 `NumericBasis` 的 supported / conditional_only / insufficient、依据类别、参照适用性、未知影响及限制。外部依据必须有已验证正文引用，用户自述依据必须有原文陈述；最终模型仍可拒绝数值、改为明确的方向或条件判断。模型的适用性判断本身未经效果验证，程序检查不能替代领域真实性审查。

普通模式默认请求可支持的主观判断，连续目标目前只支持方向/条件输出。通用 reference_class、时间序列拟合、因果效应估计、自动校准未实现。现有12窗口软件发布基线仍仅在实验路径运行；普通报告可以解释历史或时间表参照，但不能借此声称运行了统计估计器。

## 5. 时点与证据版本

实时采集使用暂定研究目标；研究和阅读完成后，程序创建最终事件版本，固定证据截止 Tc，并把既有正文快照关联到该版本。新证据关联保存 `derived_from`，保留原始获取/入库时间与哈希；不重抓网页、不改写旧文档。关联是对原快照的复用，不是声称后来网页在过去可见。

当前采用保守的近未来窗口：相对目标的 T0 为固定截止时的剩余会话时间预算加1秒之后，随后观察30天或指定时长。这样可以在受控生成时间内完成提交，用户无需填写ISO时间。报告展示准确起止。它不是“提交瞬间起算”的精确实现，会有通常数分钟的明确准备间隔。固定绝对窗口不受该默认调整。

ForecastService 在保存新版预测前复核尚未到窗口开始；超过时点拒绝保存为事前预测。相对窗口重试可显式继续另建输入版本，固定窗口已开始则拒绝。Tc 后的新资料不进入已固定的最终输入；新分析另存版本。

旧实验仍先锁定 Tc/T0，资格规则不变；新版自动评估拒绝 `experiment=True`，新版预测拒绝借用旧实验资格。独立比较新版必须新增预登记方法/批次及对应评估适配，不能改写旧协议或将普通分析成绩混入旧组。

## 6. 持久化、兼容与恢复

- 会话 Schema 1.5 兼容读取1.0–1.4，新增 `AssistanceState` 保存阶段、计划、澄清额度、研究次数、阅读结果、最终版本与预测ID；不新增数据库表，迁移头仍为 `0006_evaluation`。
- 已有 Forecast Schema 1.0、judgment-1.0、forecast-1.0、Reader和旧实验入口保留。新增可选字段为空时不参与序列化，防止改变旧冻结哈希；新预测写2.0。
- 原旧实验最终生成仍使用旧输出Schema，不因Python模型增加可选字段而暗改锁定的实验提示上下文。
- 普通评估版本为2.0，人工评估仍为1.2；各自按对应规则检查失效。模型审查通过 `review_origin=model` 和模型/提示词标识记录。
- JSON报告投影新版为1.1，旧预测仍导出1.0。全文模型输入与网页正文不进入公开报告投影；目标、推断与引用仍可能包含私人信息。
- 模型调用复用持久化预算与有限修复；失败不降级成空成功。运行中断保留费用未知，恢复需明确处理原执行状态。已保存预测可找回，不因进度标记缺失重复生成。
- 用户补充触发新档案与受影响步骤重算，旧预测保留，澄清额度不恢复。新旧模式切换不迁移或覆盖旧历史。

升级前停止进程并备份完整 DATA_DIR。旧程序不能读取新版会话/预测；回退应恢复备份，不能只改版本号。新事件语义审查枚举与派生证据字段是公开合同扩展，外部消费者需同步支持。

## 7. 验收与仍需完成的工作

离线验收覆盖自动路径、没有外部证据时的明确判断限制、用户事实支持主观概率、未知保留、一轮澄清、授权查询、两轮研究、精确引用失败、固定窗口拒绝、时点、冻结、恢复和旧记录兼容。离线模型均为显式测试夹具，不能作为真实预测案例。

后续真实验收必须检查：目标忠实度、首轮追问必要性、引用相关性、参照合理性、方向判断是否泛化空洞、查询是否覆盖关键因素、调用成本和人工负担。新旧预测方法的准确性用独立前瞻批次比较；发布预测之外的领域另行验证。人工负担、方向/条件/拒绝覆盖指标应在新实验协议中预登记，不能用本轮程序测试代替。

实际执行的命令及结果记录在[CHANGELOG](../../../CHANGELOG.md)。历史T06–T11验收文档保留原时点含义；本文件描述本次普通主线的增量，不把历史通过结果改写成新版效果证据。
