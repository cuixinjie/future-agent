# 减少预测交互负担，保留证据与准确性门槛

> 历史资料：保留编写时的实现、计划及验收结论，不作为当前使用说明。当前入口见 [文档导航](../../README.md)。

日期：2026-10-29。状态：局部流程修复已实现；下列效果评估为待执行方案。

## 问题判断与本地证据

用户反馈成立为需要调查的产品问题，但仓库没有这些用户会话、部署版本或聚合遥测，不能声称已复现所有反馈或量化发生率。

当前普通 `chat` 已有整会话一轮、最多三问、系统拟定目标、自动研究和主判断。高级 `chat --manual` 仍有人工表单；应先核对反馈来自哪个入口和版本。不能把已有能力重复当成本次新增，也不能简单取消所有必要澄清。

代码发现一个确定的浪费：`AssistanceService.answer` 原来把空答案统一追加成新来源，重新 Reader、规划，再清空当前阅读和查询授权；研究后跳过问题也走这条路。用户没有提供新事实，却承担更多等待与重新授权，旧资料虽仍存储，当前分析可能不再使用它们。

[最近真实复验](../validation/15-R06真实链路复验-2026-10-29.md)另记录约337秒累计执行计时、7次模型尝试中有超时和校验失败、研究部分完成。该例无澄清，说明慢和难交付还有服务及预算因素，不能只改追问提示词。

报告已有主判断，但问题/期限及数值在后续长段落中；用户需要很早知道“预测什么、何时、结论是什么”。

## 专业资料与采用边界

本次检索覆盖判断预测、LLM预测系统、选择性澄清、人机交互及独立效果评估。以下读取了原作者页面或论文正文，不以搜索摘要替代全文证据。

| 资料 | 支持的原则 | 本项目采用边界 |
|---|---|---|
| [Hyndman与Athanasopoulos：判断预测](https://otexts.com/fpp3/judgmental.html) | 结构化方法、及时信息和领域知识有价值；有适用数据时以统计方法作为起点 | 缺少历史数据不等于不能判断，但不能虚构基础率或校准 |
| [Halawi等，2024](https://arxiv.org/html/2402.18563v1) | 检索、推理和聚合组成可检验的预测系统 | 支持研究增强的方向，不证明本项目或增加调用次数必然更准 |
| [AIA Forecaster，2025](https://arxiv.org/html/2511.07678v1) | 高质量检索、预测协调及统计校准共同构成系统；报告的市场比较仍有局限 | 不因论文成绩直接增加多智能体或照搬校准参数；本地必须另评估 |
| [Zhang与Choi，2023](https://arxiv.org/html/2311.09469v1) | 分开研究何时问、问什么、如何利用答案；选择性澄清优于任意分配交互预算 | 研究任务为问答、翻译及推断，不能外推为未来事件准确率保证 |
| [Dong等，2026：信息价值](https://arxiv.org/html/2601.06407v1) | 问题预期收益应与用户认知成本一起考虑 | 借鉴决策原则；不让模型编造信息价值数值作为确定性门禁 |
| [Amershi等，CHI 2019](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) | 明确能力、局限，支持高效交互和纠正 | 交互研究不能证明预测更准确 |
| [ForecastBench，2025修订版](https://arxiv.org/abs/2409.19839) | 动态未来问题及统一评估支持检验预测能力 | 用未知结果的前瞻冻结比较；历史论文排名不代表当前模型排名 |

共同推论：系统应承担研究与判断，交互只用来消除实质歧义；减少交互成本的同时保留信息。不是把所有未知压成一个百分比，也不是强制每次输出方向。

## 本次实现

1. 仅当空答案来自研究后私人事实澄清，且目标可用、当前来源及事件版本未变、已有阅读且研究版本仍匹配时，直接恢复到 `reviewing`。保存跳过记录及每个未回答问题的判断影响，保留正文、阅读结果、查询授权、研究轮数和共享预算。不重新 Reader/规划，不重复联网。
2. 真正补充事实仍生成新事件并重新分析；目标歧义或状态已变化继续原有处理，不静默采用未经确认的目标。一次澄清额度不重置。
3. 确定性报告首屏展示已保存的问题、窗口、交付类型、主判断与已有主观概率。保留未校准标记；无数值的交付不补数字。完整依据、限制和历史快照继续可查。

跳过记录通过会话账本和评估限制进入最终判断，未回答的问题没有被认定已解决。固定绝对窗口、网络失败、引用及概率校验仍执行。

没有依赖、数据库迁移、Schema、提示词或预测算法版本变化；本次改变普通编排和确定性显示。旧预测及冻结哈希不修改；重新渲染新格式不改变存储的判断。旧人工/已锁定实验规则保持原样。对新的流程比较应额外预登记代码提交版本，不能只靠 `judgment-2.0` 区分编排行为。回退代码可读取相同合同，但再次遇到未处理的跳过会恢复旧的重复分析行为。

## 与直接问LLM的区别应如何证明

当前实现的差异是目标/时间契约、可核查正文快照及引用、研究预算和停止、证据资格、不可覆盖的冻结、到期核验与评分。它们让预测可追溯、可检验，不自动构成准确性优势。若同模型直接预测在相同问题上效果相当且成本更低，就必须承认当前系统的增量价值尚不足。

## 后续准确性与体验验收（未执行）

- 先收集脱敏问题、入口、版本、耗时和停止原因，按目标歧义、公开事件、私人事实不足、渠道失败分别检查。统计内容澄清、授权次数、重试次数，避免只看“澄清一轮”掩盖总交互负担。
- 真实语义回归检查目标忠实度、未知是否进入结论、必要澄清与跳过行为、证据是否仍适用。拒绝强行数字和空泛方向；记录全部交付类型和执行失败。
- 前瞻比较旧普通流程、新流程、同模型直接预测及适用的历史基线。预登记模型、代码/提示词、预算、共同截止快照、目标、结果规则及私有信息可见范围；首次预测冻结后等待结果，不用已知结果调参再称独立测试。
- 准确性比较采用配对Brier差值，同时报告概率覆盖、方向判断覆盖、条件分析、拒绝和失败比例。只在共同数值子集上评分不足以排除选择偏差，必须展示全部登记样本与子集构成。方向正确性和目标忠实度另评估，不把方向硬转成概率。
- 非劣效界值、置信水平、样本量依据及缺失规则须在看到结果前锁定；“差异不显著”不等于准确率不下降。本次没有足够数据选择可信界值，不伪造通过标准或成绩。
- 体验同时看首次有效交付耗时的中位数/P95、用户输入次数、重复授权、模型调用、token和已知成本。只有准确性门槛与覆盖未恶化且负担下降，才宣称优化有效。现有评分工具不代表已实现这份方案全部指标或多组编排。

当前可验证的是：在相同已读材料且没有新增事实时，避免重复分析并保留判断输入。真实模型输出仍可能变化，不能承诺“准确率绝对不受影响”。不以停止追问为由降低证据门槛，也不通过多拒绝难题美化成绩。
