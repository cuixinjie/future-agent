## 使用

先使用 M1 创建并保存至少一个事件版本；可用 README 中的人工档案流程，无需模型。以下命令中的会话 ID、事件版本和文档 ID 替换为实际值：

```powershell
uv run --locked future-agent schema evidence
uv run --locked future-agent evidence import <会话ID> --revision 1 --input tests/fixtures/evidence/webpage.fixture.json
uv run --locked future-agent evidence list <会话ID> --revision 1
uv run --locked future-agent evidence show <文档ID>
uv run --locked future-agent evidence text <文档ID>
uv run --locked future-agent schema span
uv run --locked future-agent evidence cite <会话ID> --revision 1 --input data/span.json
uv run --locked future-agent evidence spans <文档ID>
uv run --locked future-agent evidence select <会话ID> --revision 1 --cutoff <带时区截止时间>
```

所有命令沿用全局 `--data-dir`、`--no-env` 等配置。`evidence text` 显式显示完整原始正文和规范化正文，请勿直接公开第三方资料或私人输入。

T06 本文记录其初始 1.0 契约。T07 已将来源/导入契约升级为 1.1，新增 final_url、date_hint 和 network 来源，旧格式可读取；兼容、备份及回退要求见 [T07说明](08-T07搜索与网页读取.md)。T06 导入命令本身仍不联网。

## 契约与数据流

`JsonMaterialImporter → MaterialImporter → EvidenceService → EvidenceRepository / SnapshotStore`。CLI 负责装配，应用服务执行事件绑定、引用和资格规则，SQLite 与文件适配器执行 I/O。新增对象沿用 `schema_version=1.0`；M1 对象、Reader 提示词、模型配置和实验方法版本不变，无新增依赖。

导入 JSON 包含 `url`、可空的 `publisher/title/published_at/modified_at/retrieved_at`、`access_status`、可空的 `raw_text/snippet/failure_code` 和 `origin=manual|fixture`。日期必须含时区，内部转换 UTC。来源日期由导入者提供，程序检查一致性，不代表已经独立核实。

- `read_success` 必须有非空正文；`candidate_only` 和 `fetch_failed` 不得带正文。失败必须有标准 `failure_code`。没有获取日期保持 null，不推断为发布日期。
- 原始文本只进行 CRLF/CR → LF 转换，不删除空格、BOM 或改变 Unicode。正文哈希为规范化文本 UTF-8 的 SHA-256。`EvidenceSpan` 的 `[start,end)` 使用这份文本的 Python 字符串索引，不能按原始换行、UTF-8 字节或 JavaScript UTF-16 偏移计算。
- 引用关联 `document_id`，文档绑定不可覆盖的 `event_revision_id`；`claim_ids` 只能来自同一事件版本。引用切片不匹配、跨版本或候选摘要引用均拒绝。
- URL 限 HTTP(S)，拒绝用户信息、空白和反斜杠；统一协议/主机大小写、IDNA、默认端口和空路径，移除 fragment，保留路径和查询参数语义。URL 只是来源标识，此处不访问地址；T07 仍须独立执行 DNS/SSRF 检查。
- 每次导入新增来源记录。相同 URL 的变化正文另存，不覆盖历史；不同 URL 的相同正文保留全部来源，但共享规范化正文文件。引用不会自动把 M1 的用户陈述升级为已核实事实。

## 日期资格与去重

`evidence select` 对指定事件版本逐条返回资格和排除原因，默认按实验模式拒绝 `fixture`。仅离线演示可增加 `--allow-fixtures`。通过只表示已读和时点资格，不代表统计资格、预测可信度或实验协议已经封存。

正文已读、获取时间已知，且获取、本地入库、已知发布和修改时间均不晚于截止时点，才允许进入候选实验输入；等于截止时点可以通过。旧发布日期不能绕过后来入库的限制。T06 不支持证明离线档案在过去已封存，因此截止后导入的历史档案也保守排除。发布/修改日期未知可保留；若系统已在截止前取得并保存正文，仍有本地可用时点依据。

合格正文按内容哈希去重，以入库时间、文档 ID 顺序选择代表文档；其他记录返回 `duplicate_content`，全部来源和引用仍可读取。缺失正文、获取失败、未知获取时间和截止后资料保留各自原因，不变成空成功。创建引用、读取已有引用和接纳正文前重新校验内容哈希；文件缺失或损坏明确失败。

这只是资料筛选接口，尚未执行 T11 的协议绑定、输入哈希集合和截止封存。T07 的网页网络安全与预算已实现，见 [T07说明](08-T07搜索与网页读取.md)；T08 的数据条件及方法资格已实现，见 [T08说明](09-T08数据条件评估.md)。

## 保存、升级和回退

迁移 `0002_evidence` 在 `0001_m1` 上新增 `evidence_documents`、`evidence_spans` 表及事件/文档关系；不改写 M1 历史。首次运行数据库命令会升级，升级前应备份数据库和整个 `DATA_DIR/evidence`。未知数据库版本继续拒绝；降级明确拒绝删除证据，回退使用升级前备份配合旧版程序。

`DATA_DIR/evidence/text/<正文SHA-256>.txt` 保存共享规范化文本；`raw/<snapshot_id>.txt` 保留原始文本，ID 为原始文本 SHA-256 前128位对应 UUID。同一正文的不同换行版本可共享规范化文件并保留各自原文。数据库保存内容哈希和快照 ID，路径由适配器生成，不接受导入者指定路径。文件不得通过符号链接越出批准目录，已有文件内容不一致时拒绝覆盖。

每个文件先在同目录临时文件中写完、刷新并同步到磁盘，再通过硬链接原子创建最终文件名；不替换已有文件，并发写入相同内容仍可成功。数据目录所在文件系统须支持硬链接（如本地 NTFS）；不支持时明确失败，不回退为覆盖写入。常规写入失败清理本次临时文件；进程被强制终止可能留下临时文件，但不会把半文件发布为有效快照。

原始和规范化正文都保存成功后才记录 `imported_at`，数据库事务随后保存。若写入跨越截止时点，不能使用较早的导入开始时间通过筛选。事务失败仍可能留下未关联的完整文件，T06 不自动清理这些文件，避免误删共享快照。文件、元数据和本地系统时间不是防篡改归档；发现内容不一致会拒绝使用，不能声称具备外部存证能力。

验收修复保留显式 URL 端口 `:0`，不再错误地合并为默认端口；历史版本若曾保存这种 URL 的错误规范值，应保留原记录并重新导入，不得原位覆盖。已检查本工作区数据库，无此类历史证据，无需数据迁移。对象格式和数据库版本不变；截止筛选结果应按修复后的程序重新计算，T06 未持久化资格缓存。
