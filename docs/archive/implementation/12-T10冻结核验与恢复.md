## 冻结与修订

```powershell
uv run --locked future-agent forecast freeze <预测ID>
uv run --locked future-agent forecast frozen <预测ID>
```

`FrozenForecast`（Schema 1.0）独立保存完整 T09 Forecast：事件及问题版本、结果定义、评估、证据文档及精确引用、截止时点、方法/模型/提示词/结构化模式、原始概率和归一化结果、调用 ID；另存冻结时间、确定性 SHA-256 和计算参数 `probability_tolerance=1e-6`。正文继续使用 T06 的不可覆盖内容寻址文件，冻结前实际读取并检查原始及规范化正文完整性；不会重新联网补资料。哈希用于检查内容一致性，不提供针对手工篡改整个数据库的签名保证。

相同内容重复冻结返回原冻结时间；不同内容或冻结规则拒绝覆盖。冻结不修改原 T09 草稿，历史草稿也不会自动算作已冻结。

`forecast report <预测ID>` 通过应用服务读取冻结状态：未冻结显示草稿；已冻结使用封存对象生成报告，并展示冻结时间和内容 SHA-256，不再显示“尚未冻结”。冻结本身不代表已获得实验评分资格；T11 的全登记与评分条件见 [T11说明](13-T11实验运行与评分.md)。报告不改写原草稿、冻结内容或哈希。

修订先用 `forecast run` 产生新的预测，再显式关联：

```powershell
uv run --locked future-agent forecast freeze <新预测ID> --supersedes <旧预测ID> --reason "补充证据后重新判断"
```

旧预测须已冻结；修订须属于同一会话且创建时间晚于旧预测。目标、窗口、结果类型、判定及来源规则、结果定义或提前核验规则变化时，须作为独立预测，不能用于重新解释旧概率。修订保存前驱及理由；T11 仅接受协议首次提交，更新不能回填首次条目。

## 手动核验

使用已有 `evidence import` 与 `evidence cite` 导入结果正文并创建引用，绑定被核验预测的事件版本。结果资料允许晚于事前截止时间；它们只进入核验记录，不会改写已冻结输入。

首次未决登记文件示例：

```json
{
  "schema_version": "1.0",
  "status": "pending",
  "resolved_outcome": null,
  "evidence_ids": [],
  "resolver": "核验人姓名或标识",
  "reason": "观察窗口尚未结束或来源记录不完整"
}
```

```powershell
uv run --locked future-agent resolution record <预测ID> --input <登记文件.json>
uv run --locked future-agent resolution history <预测ID>
uv run --locked future-agent resolution record <预测ID> --input <下一次登记.json> --expected-previous <最新核验ID>
```

`ResolutionInput` / `Resolution`（Schema 1.0）支持 pending、resolved、disputed、void。首次登记省略前驱，之后必须提供最新核验 ID；数据库使用预测 ID 与递增序号唯一约束，防止并发提交丢失历史。每次登记保留人、理由、时间、前驱以及结果引用和来源元数据。未登记不表示已发生或未发生；可以先显式登记 pending。

只有 resolved 携带 `resolved_outcome`，它必须是冻结结果键，且至少提供一条可定位、完整性检查通过的正文引用。`resolved_at` 由程序设置为本次登记时间，其他状态为空。争议或作废后可以追加新的核验，历史不改写。理由应说明如何按冻结的规则判断，尤其是无发布结果需要完整窗口及充分官方记录；程序不冒充人工判断来源真实性。

默认必须等待完整观察窗口，未决不能补为负例。设计允许已确认的发生结果提前核验：冻结时通过 `--early-outcome <发生结果键>` 显式预登记可提前确认的结果；提前 resolved 必须附 `observed_at`，且在 `(window_start, window_end]` 内并不晚于登记时间。不得把“尚未发生”的结果设为可提前核验。程序校验冻结键和时间边界，发生语义及来源充分性由人工审查。实验专用统一核验时间、官方来源规则、截止封存及迟交资格由 [T11工具](13-T11实验运行与评分.md) 执行，真实观察属 T12。

## 持久化步骤与恢复

```powershell
# 先生成 UUID，保留它作为步骤幂等键
uv run --locked future-agent forecast run <会话ID> --revision <版本> --assessment-id <评估ID> --input examples/forecast-spec.json --request-id <步骤UUID>
uv run --locked future-agent forecast step <步骤UUID>
uv run --locked future-agent forecast resume <步骤UUID>
uv run --locked future-agent forecast resume <步骤UUID> --retry-interrupted
uv run --locked future-agent forecast cancel <步骤UUID>
```

每次新运行持久化 `ForecastStep`（Schema 1.0），状态为 ready/running/completed/cancelled，保存会话与事件版本、评估 ID、结果定义、数值开关、模型、结构化模式、输出 token 上限、提示词/方法版本和产物 ID。未指定 request-id 时生成新的步骤；需要安全重发创建命令时应由调用方提前提供 UUID。相同键和输入返回或恢复原步骤，换输入拒绝；有意再次预测使用新键。

会话保存 `active_forecast_step_id`。未提前保留键时，可用原有 `resume <会话ID>` 查看会话的活动步骤；该命令不代替 `forecast resume`。产物写入、会话完成和步骤完成同一事务提交，重复恢复 completed 直接返回原预测，不再请求模型，即使后来事件已修订仍返回原产物。

恢复未完成步骤前检查事件版本、评估失效、证据文件、模型配置、方法/提示词版本和取消标记。running 步骤需要显式 `--retry-interrupted`；保留旧尝试、token/时间预留和未知费用，再在剩余额度内调用，不能承诺外部服务严格执行一次。模型返回但本地事务未提交时，同样不能把它声称为成功产物。T09 旧草稿无步骤记录，仍可查看与冻结；旧中断任务继续使用原有显式 abandon。

cancel 持久化标记，不删除历史；每次新增模型调用前和返回后检查，取消后的迟到结果不保存，实际用量仍留存。同步 HTTP 不能立即强制打断；等待有界调用返回。进程已经退出且会话仍锁定时，取消后需用 `forecast abandon <会话ID>` 明确确认中断并解锁；已取消步骤不能恢复，已完成产物不能取消删除。

当前仍是本地顺序 CLI，不提供多进程工作者租约。`--retry-interrupted` 应在确认旧执行者已停止后使用；T14 才负责领取和租约。预算、步骤和调用记录在重试中不重置。

### 2026-10-22 审查修复：调用归属和夹具标记

模型调用在发出前随预算预留一起保存 `CallAttempt.forecast_step_id`。恢复、格式修复和重试继续使用原步骤 ID；新预测只关联自己的调用，即使旧步骤被放弃后先运行另一份预测，再恢复旧步骤，也不会混入其他步骤的费用。预测 `attempt_ids` 包含本步骤的已知失败、中断和成功尝试，SQLite 提交时复核完整归属；会话预算仍包含全部读取和预测尝试，费用未知继续为空。

旧 1.0 调用没有步骤归属时，读取为 `forecast_step_id=null`，保留原 ID、用量和预留。它可能来自 Reader 或历史预测，不能仅按时间或列表位置认领。恢复旧步骤后新增的调用可追溯，旧的未归属调用仍只计入会话总预算；不能将该步骤已关联调用的合计声称为完整历史成本。已保存、已冻结预测的 `attempt_ids` 不回填或改写。

夹具属性在同一会话的后续确认、编辑、回答和重新读取中保留；Reader 的原文和语义校验仍按实际读取操作执行。存在明确夹具历史的会话即使经过旧版丢失标记的人工修订，下一次修订也恢复夹具标记；历史版本不重写。其新研究来源标记为夹具，默认实验筛选排除，预测报告保留夹具提示。真实输入须建立独立会话。

## 兼容与迁移

- 新迁移 `0005_lifecycle` 只新增 frozen_forecasts、resolutions、forecast_steps 三表，不重写 T09 及以前的记录。
- T10 初次实现会话 Schema 1.3；本次审查修复升至 1.4，兼容读取 1.0–1.3。CallAttempt 升至 1.1，兼容读取 1.0，新增可空的步骤归属。原数据库 payload 不在读取时回写，后续正常保存才使用新合同。该次审查修复时迁移头为 `0005_lifecycle`，无需新增表或重写历史；T11 后续另新增 `0006_evaluation`。旧程序不支持新会话/调用合同。
- T09 Forecast、FrozenForecast、事件、证据、提示词、预测方法及实验协议版本不变；冻结内容及其 SHA-256 不变，不失效现有评估。旧数据缺失的归属保留未知，不推断或补造历史。
- 升级前备份完整 DATA_DIR（数据库和 evidence 文件）；未将开发测试直接指向用户 DATA_DIR。降级拒绝删除历史；回退使用升级前备份。旧程序不支持新会话合同。
