# M2-T08：数据条件评估与方法资格

> 历史资料：保留编写时的实现、计划及验收结论，不作为当前使用说明。当前入口见 [文档导航](../../README.md)。

> 2026-10-27 普通主线已改造。本页保留原阶段、分步人工/旧实验路径与当时验收语义；默认chat的自动研究、交付类型、时点和新合同见[预测主线改造决策](../decisions/预测主线改造.md)。旧冻结、协议及历史验证结果不改写。

T08 在现有证据服务上增加确定性评估服务，不联网、不调用模型。引用相关性和关键条件由显式人工审查输入，程序负责快照、版本、截止资格、去重与方法门禁。人工判定仍可能错误，引用可追溯不等于事实真实。

## 使用

先确认完整预测问题，用 T06 导入或 T07 研究获得正文，再用 `evidence cite` 保存精确引用。评估使用问题自身的 `forecast_at` 作为截止时间，不能通过 CLI 另选宽松截止时间。获取及本地入库晚于截止的正文不进入评估；需要后续新资料时，另建含新预测时点的事件版本。

创建 UTF-8 审查文件，例如 `data/review.json`：

```json
{
  "schema_version": "1.0",
  "reviewer": "本地使用者",
  "evidence": [],
  "critical_questions": [],
  "limitations": ["尚无相关正文引用，当前仅可讨论条件情景"],
  "allow_numeric": false
}
```

有合格引用时，在 `evidence` 中登记以下对象，替换为真实引用 ID。`purpose` 可为 `current_state`、`counterevidence`、`mechanism`：

```json
{
  "span_id": "填写 evidence cite 返回的引用 UUID",
  "purpose": "current_state",
  "relevance_reason": "说明该原文与当前目标的关系"
}
```

```powershell
uv run --locked future-agent schema review
uv run --locked future-agent assessment run <会话ID> --revision <当前确认版本> --input data/review.json
uv run --locked future-agent assessment show <会话ID> --revision <版本>
```

默认排除 fixture 资料；离线验收显式添加 `--allow-fixtures`，结果保存 `experiment=false`，不能据此声称真实实验资格。缺少当前正文时可以保存空审查，明确报告缺口；传入不存在、其他版本、不合格或内容重复的引用则拒绝，不能静默丢弃。

## 输出与方法门禁

`EvidenceAssessment` 为 `schema_version=1.0`，当前评估规则版本为 `evidence-assessor-1.2`（T09 为 `1.1`，此前为 `1.0`），保存事件/问题 ID、截止时间、实验标记、输入哈希、人工审查、研究运行状态及原始缺口、逐来源资格及排除理由、陈述覆盖、当前未知、限制、缺口和方法理由。

- 陈述覆盖只取人工标注为当前状态的引用所关联的 `claim_ids`，不计算真实性分数；机制和反证不自动计作当前状态覆盖。
- 默认推荐 `scenario_only`。完整已确认目标、有人工审查的当前证据、显式开启数值估计、没有人工登记的关键阻断问题时，可推荐 `llm_judgment`；普通当前未知仍保留，不自动判为已解答。
- `methods[].data_eligible` 表示当前路径所需条件，`implemented` 表示可执行实现；`available_methods` 严格取二者交集。T09 已注册情景与主观判断引擎，两者可按资格进入可用方法；实验专用发布频率基线在 T11 实现，但通用评估缺少专用历史资格，仍不会自动开放；其他统计方法未实现。旧评估不重写，需重新评估后使用新引擎。
- 通用参照数据、时间序列及发布频率基线均未接入对应资格验证与估计器，明确记录不合格/未实现。网页条数、重复报道、已读正文均不自动成为统计样本。
- `critical_questions` 最多三个；非空时评估返回 `status=needs_input`，问题原样保存。评估结果状态独立于 M1 会话状态，本步骤无模型长任务，不新增会话执行状态。使用既有 `answer`/`edit` 补充信息，再核对目标并 `confirm`，产生新事件版本后重新研究和评估。
- 案例分支固定 `skipped`，保留理由，不视为失败；没有案例不会阻断条件情景路径。

## 持久化、失效和兼容

新增 Alembic `0003_assessment`，只新增 `evidence_assessments` 表；既有会话、事件、证据、提示词及实验协议格式不变，无新增依赖。仓储拒绝同 ID 覆盖，重复运行另存评估。

升级前备份完整 DATA_DIR（数据库及快照），并停止写入。迁移不重写已有记录；破坏性降级明确拒绝，回退请停止应用并恢复升级前的完整备份。旧程序不能假定认识新迁移版本。

输入哈希包含该版本的全部来源元数据、正文哈希、引用及对应研究运行状态和缺口，引用读取复核快照。`show` 保留原评估并返回 `stale` 与原因：事件版本改变为 `event_revision_changed`，新增来源或引用为 `evidence_inputs_changed`。T09 新增评估规则变化原因 `assessor_version_changed`，旧记录需重新评估，详见 [T09说明](11-T09情景与主观预测.md)。没有跨版本缓存复用。正文损坏直接报错，不包装为成功评估。评估期间检查会话及证据变化；本地顺序执行是当前使用约定，不提供多工作进程事务快照隔离。T11 已实现专用实验封存，具体隔离与兼容规则见 [T11说明](13-T11实验运行与评分.md)。
