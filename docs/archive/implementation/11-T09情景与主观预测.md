## 使用与输入审查

先完成目标确认、正文导入/研究、精确引用及 `assessment run`。需要数值时，人工审查必须
`allow_numeric=true`、至少有一条经审查的 `current_state` 合格引用、没有 `critical_questions`。
关键条件未明时仍可生成条件情景，问题和未知会保留。反证缺失明确列为缺口。

将 [结果定义示例](../../../examples/forecast-spec.json) 复制到数据目录，按当前问题修改并审查。
`definition_review` 记录定义如何对应目标、窗口与核验规则，不能将示例机械用于其他问题。
二元问题要求两个互斥穷尽结果；数值分类也要求 `exclusive_exhaustive`。分类定义及穷尽性由人
审查，程序不宣称理解并证明自然语言定义。重叠的不同指标应拆成独立二元问题；连续问题本阶段
仅提供无概率情景。非互斥条件方向可用 `independent` 情景模式，不对其求概率分布。

```powershell
uv run --locked future-agent schema forecast-spec
uv run --locked future-agent forecast run <会话ID> --revision <当前版本> --assessment-id <评估ID> --input data/forecast-spec.json
# 数值模式：同一命令显式加 --numeric，仍须通过资格检查
uv run --locked future-agent forecast history <会话ID> --revision <版本>
uv run --locked future-agent forecast show <预测ID>
uv run --locked future-agent forecast report <预测ID> | Set-Content -Encoding utf8 data/forecast-report.txt
```

`forecast-spec`、`forecast-draft`、`forecast` 均可通过 `schema` 命令查看。
情景与数值模式均需要配置模型；未配置不会使用模拟输出。预测会把事件档案（包括私人陈述）、
审查、合格引用及来源元数据发送给配置的模型服务，不自行联网补事实或搜索。
本地 JSON 和报告可能包含私人信息及第三方片段，不能直接视为可公开导出包。

## 领域规则与数据流

CLI 组合入口装配 `ForecastService`、`AssessmentService`、证据服务、模型和仓储。
应用服务复查评估失效、截止资格、正文完整性和当前事件，再调用共享 `ModelCalls`；
领域契约验证结果与概率，SQLite 保存，确定性报告只渲染保存的预测，不再次调用模型。

- 结果键、顺序与人工定义逐一匹配，禁止新增、遗漏、重复或由模型改换定义；
  引用只能指向该评估审查过、通过截止资格的片段。空方向集合失败，空支持/反证列表明确报告缺口。
- 概率拒绝布尔值、字符串、NaN、无穷和越界值。情景模式所有概率必须为空；
  数值模式须完整输出，或全部为空并保存明确的 `refusal_reason`。拒绝不是服务故障，缺失不补值。
- 互斥穷尽概率和与 1 的绝对差须不大于 `1e-6`。只有容差内误差可归一化，
  `draft` 保存原值，`normalization_original_sum` 留痕，`probabilities` 是报告使用的有效值。
  不裁剪非法数字，也不将自评信心或案例条数变成概率。
- `Forecast` 保存事件/问题、评估、结果定义、截止时间、合格来源元数据和引用文本、方法版本
  `judgment-1.0`、模型标识、提示词 `forecast-1.0`、结构化模式及调用 ID。
  模型标识由用户配置服务提供，不代表已锁定供应商内部权重。没有案例仍可正常完成。
- `render_report` 从上述对象生成窗口、判定规则、方向、原有数值、引用、未知和缺口。
  每次读取都复核预测契约，不重新判断世界；后续事件/证据变化不改写历史报告。

## 预算、失败与中断

Reader 与预测复用持久化模型调用器。搜索及模型共同消费会话总时间，模型调用/格式修复/
有限重试共同消费调用数和 token。请求前预留，缺少用量或中断保留保守扣款，价格未知为 `null`。
格式修复最多两次，暂时性错误最多重试两次，迟到响应不接纳。结构、引用或概率持续非法时
保存错误并失败，不保存空成功预测。修复提示不回显供应商原文和校验输入。

预测执行时会话为 `FORECASTING`，读取、编辑、回答、研究及新评估被阻止。
模型返回后再检查输入版本和证据完整性；变化或损坏则拒绝结果。保存草稿和恢复
`STRUCTURED` 在同一数据库事务内完成，写入失败不会留下完成状态。

进程中断后先用 `show` 查看会话，`forecast history` 查找已提交的草稿。若仍在执行状态，
确认执行进程已停止后，使用 `forecast abandon <会话ID>`，将未完成尝试记为费用未知并解锁；
已消费/预留预算保留。再次 `run` 是新草稿，可能产生新费用。T09 不提供请求幂等复用或自动续跑，
T10 已实现正式步骤恢复（见上文链接）；不承诺外部请求严格执行一次。仅支持本地顺序执行，未提供多进程证据事务隔离。

## 版本、迁移与回退

新增预测及结果定义契约 `schema_version=1.0`；会话升级至 `1.2`，兼容读取 `1.0/1.1`，
仅在保存会话时写新版本。Reader 提示词、既有事件/证据/协议契约和实验方法不变，无新增依赖。
T09 当时的 T08 方法登记启用 `scenario_only/llm_judgment`，评估规则版本升至 `evidence-assessor-1.1`；T11 后为 `1.2`，旧评估不改写，下次预测前需重评，见 [T11说明](13-T11实验运行与评分.md)。
旧 `1.0` 评估照常读取、不改写，查看时增加 `assessor_version_changed` 并要求重新评估；
不把旧评估中空的可用方法自动变成可执行资格。

迁移 `0004_forecasts` 只增加 `forecasts` 表及索引，不改写旧事件、证据或评估记录。
运行任何会打开数据库的 CLI 前，停止写入并备份完整 `DATA_DIR`（数据库及快照）；
自动迁移不代替备份。破坏性降级拒绝执行；回退旧程序时恢复升级前的完整备份。
同 ID 预测拒绝覆盖，重新运行生成另一个草稿；这些本地不可覆盖草稿尚未具备 T10 正式冻结语义。
