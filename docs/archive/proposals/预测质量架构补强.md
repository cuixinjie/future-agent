# 预测质量架构补强：参照、研究价值、推断审查与无用户评估

> 历史资料：保留编写时的实现、计划及验收结论，不作为当前使用说明。当前入口见 [文档导航](../../README.md)。

日期：2026-10-29。状态：设计完成、待实现与效果验证。本次响应“先从理论与专家实验入手”；本文件不把候选算法注册为生产能力，不修改旧冻结结果。文献证据及实际数据获取检查见[研究记录](16-预测质量文献证据.md)。

## 1. 目标与选择

目标是在没有真实用户时，形成有根据的预测方法、可重复的开发评估和可展示的前瞻记录。通用自然语言入口保留；能力按问题族声明，软件稳定发布作为第一个完整数据适配目标，公开跨领域题库作为迁移诊断。软件题结果不能证明个人处境或产品经营预测能力。

本项目现有M1–M3与普通CLI可以承载流程，但 `NumericBasis` 多为模型解释，普通路径没有可计算历史参照入口；引用校验不能证明推断；旧实验A/B/C没有等预算交互强基线和完整消融。此次补强沿用模块化单体和现有应用服务，在下述依赖顺序中逐步实现，不新增微服务、训练平台或多智能体框架。

既有一轮最多三问仍是用户负担上限，不是“每次应问三问”或预测质量指标。数据增强先在候选实验路径实现；准确性改进与安全/结构缺陷修复分开验收。无数据时可以给有依据的未校准判断、条件分析或拒绝，不强造基础率。

## 2. 数据流和模块边界

目标与结果契约 → 证据时点与能力匹配 → 可计算参照 + 当前证据 → 待解决判断缺口 → 有界研究/必要澄清 → 结构化证据与推断审查 → 候选预测 → 可选程序聚合 → 可选已验证校准 → 保存、报告和冻结。

离线评估并行于产品开发，不等待用户：公共数据审计 → 开发/选择/封存测试划分 → 候选方法消融 → 本地未结局问题提前冻结 → 到期共同核验 → 默认方法准入。

下表均为拟新增的逻辑契约，字段名用于评审，不表示现有Python类已存在。

| 产物 | 最小字段/职责 | 所属与现有接入点 |
|---|---|---|
| ReferenceEstimate | 目标/窗口/通道、样本分母、事件数、逐窗口标签、输入哈希、方法版本、估计、适用性与局限 | 领域纯计算；应用层调用数据端口，在AssistanceService目标确定后读取；适配器负责来源 |
| DecisionGap | 缺口、目标/结果键、已知/未知/失败、答案分支及影响、公开可查性、成本类别、停止理由 | 领域契约；应用层决定搜索、询问或条件交付，替代只凭一句“影响判断”的执行依据 |
| EvidenceArgument | 文档/精确片段、主张、断言类型、时间、范围、原始来源组、支持/反证、推断连接及反面解释 | 复用EvidenceReading与现有引用；增加明确语义关系，保留模型审查来源 |
| ReviewFinding | 规则、关联对象、严重度、程序/模型/人工来源、证据及处置 | 扩展领域校验与评估；硬失败拒绝、软风险保留，不把模型标签变成已核实事实 |
| CandidateForecast | 共享问题/快照哈希、独立调用标识、概率/缺失原因、依据、费用和版本 | 复用预测步骤/预算；有效候选才能按预登记策略组合 |
| CalibrationArtifact | 适用模型/提示词/方法/领域、训练与选择切分、参数、指标、哈希和有效范围 | 领域变换，应用层资格控制；不自动训练或套用他人参数 |
| BenchmarkPacket / MethodReleaseDecision | 证据与标签分离、题族/事件族、模式、来源许可、方法版本、指标与准入理由 | 独立评估用例，复用冻结与评分原语；不在UI重写业务规则 |

## 3. 可计算参照：先建立外部起点，再解释当前差异

### 3.1 首个落地点

复用 `domain/evaluation.py::baseline` 的发布去重、稳定版及12个完整30天窗口规则，以纯函数作为唯一算法来源，保留 `release-frequency-1.0` 的旧实验语义。新增普通流程适配负责提取并核验完整历史记录、对齐目标和截止，不把实验用例整体复制到普通路径。

只在“同一产品与通道、未来30天至少一次稳定发布”匹配时使用该参照。不同期限、多个产品或不同发布定义返回不适用，不机械将频率按天数线性缩放。过去360天资料不完整返回缺失，不把未查到发布当未发布。

计算 `p_ref = sum(window_labels) / 12`，保存逐窗口标签和分母。0/12、12/12是观察频率，不证明未来绝无可能或必然发生。现有12窗口规则是可复用基线，不是最佳估计器或样本充分性结论；记录窗口依赖、周期改变和小样本局限。

### 3.2 参照与调整分开

报告并列保留历史参照和最终判断，避免模型把历史比例重写成自己估出的数字。每项调整关联证据与影响机制；计算最终概率与参照的差值只作审计，不声称每项差值具有因果含义。统计资格与主观调整资格分开。

用户问题和规则不能为了套基线被改写。发布时间表只是当前证据；发布周期已变、产品停止维护等变化必须影响适用性。历史频率没有考虑距上次发布时长，后续可候选比较更新过程/生存模型，但不能假定发布是无记忆泊松过程。平滑先验、收缩权重或相似项目组合须另有来源与开发验证，不把“加一”当通用准确性修复。

### 3.3 未支持领域

保留来源明确的判断参照、时间表或条件分支，并展示证据局限。没有统计适配器不应伪造跨领域“成功率”。公开市场共识可作为单独来源或基线，必须记录时点、流动性及规则匹配，并区分“含共识输入”和“独立判断”实验。

## 4. 研究与澄清：围绕可改变判断的缺口

区分四类缺口：用户目标歧义、可查公开事实、用户独有事实、未来固有不确定性。公开事实由系统研究；未来尚未发生的事不能让用户替系统回答。渠道失败是执行问题，不能改称信息价值低。

每个候选缺口必须给出至少两个可解释分支及其影响：改变对象/窗口/核验规则，改变结果排序，改变有依据的概率判断，或改变用户行动选择。已有信息可覆盖、明确跳过、同一缺口已解决者排除；模型语义去重不能冒充完美程序去重。

程序执行顺序：检查缺口键与已答状态 → 可公开研究则在授权及预算内查询 → 只有用户可答且分支影响实质判断时进入剩余澄清额度 → 无法回答时保留条件分析或限制。高置信度不是停止依据，资料数量也不是证据充分性。

### 4.1 定量信息价值何时可用

理论上，若问题与事件Y固定、答案A的分布已知且条件概率可信，在Brier损失下，获取答案的期望收益为 `Var_A[P(Y=1|A)]`。这是全方差分解对应的理想信息收益，不是让模型自由编分支概率。若涉及行动，应改用用户效用/损失下的期望决策收益，不能混用两个目标。

只有数据支持答案分布和条件概率时才计算；收益还应考虑资料能否取得、噪声、费用与耗时。缺少这些条件时保存定性影响，VOI值为未知。不同答案下概率的跨度仅是敏感性，不是置信区间或期望收益。

初版不新增模拟用户调用。模型在已有规划/阅读步骤提供结构化分支，由程序执行额度和停止。预算用完、无可授权查询或没有明确可解决缺口时停止；保留至少最终判断所需的调用和时间，未完成重要缺口进入报告。具体额外调用数须在实现时核对现有12次预算，不从论文照抄10个代理。

### 4.2 无真实用户时如何测

使用带有事前答案的封闭任务包，遮蔽一个字段，固定响应器仅在询问该字段时返回原有事实；未知字段返回未知，不能查结局或即兴编造。比较不询问、按影响选择询问和固定询问策略。该测试衡量信息利用与必要性，不能称为真实用户体验或跨领域准确率验证。

## 5. 推断审查：把支持关系写清楚

引用记录“哪里写了”，推断记录“为什么这段话支持这个结果”。拟增加以下审查点：

| 输入或推断 | 必须识别的风险 | 预期处理 |
|---|---|---|
| 官方预计下月发布 | 意图/计划不等于实际发生 | 保留计划属性，检查历史履约或当前障碍；不自动赋概率1 |
| 五篇报道转述同一公告 | 来源相关性 | 同一已知原始来源组，不将重复转述累计为五份独立依据 |
| 新闻只覆盖某个版本分支 | 范围遗漏 | 目标是任一稳定版时保留其他分支缺口，不据此判定整体不发布 |
| 搜不到发布消息 | 缺失与否定混淆 | 只有完整覆盖且核验规则允许时才构成未发生证据 |
| 收入、活跃用户同时变化 | 非互斥指标 | 分成独立问题，禁止强塞一个和为1的分布 |
| 两个必要条件各有概率 | 未知依赖结构 | 不直接相乘；需要条件概率/联合模型或保留条件分析 |
| 行动方案与成功相关 | 观察与干预混淆 | 不声称行动带来因果增益 |
| 正文存在结局或截止后更新 | 时间泄漏 | 排除出预测输入，保留失败/污染记录 |

硬检查：引用及对象归属、时点、概率、分布和字段关系由程序执行。来源组未知时保留未知，不用同域名等同来源，也不用不同域名等同独立。

软检查：反证是否遗漏、机制是否成立、来源动机、措辞与结论是否相符，保存具体片段和审查来源。模型指出风险后可有限修复或补充研究，但审查模型说“通过”不能授予统计资格。严重疑点未解决可降为条件交付；不得只删除风险标签。

上述八类构成最小语义验收清单，同时加入应当正常通过的对照，测漏报和误拦截，避免把所有预测都挡掉。合成材料只验证逻辑；另用公开真实事前资料做盲评，评审先看材料与规则，不看结局来倒推“正确理由”。

## 6. 概率生成、组合与校准

优先验证：有参照的单次判断是否优于无参照判断。必要时比较少量独立采样的等权平均，候选各自只能看相同已封存证据与目标，不先互相看答案。同模型多次调用有相关误差，不是独立证据。

对于同一二元问题、同一结局y，等权概率平均满足：`mean((p_i-y)^2) = (mean(p_i)-y)^2 + mean((p_i-mean(p_i))^2)`。所以平均的Brier不大于这组成员的平均Brier。这一代数性质不保证优于最佳成员，也不保证值得多倍成本；完全相同的错误没有收益。先以它作为组合对照，再评估主动查证分歧，而非让模型挑“最像专家”的答案。

所有候选必须匹配目标、窗口、快照和概率语义；缺失不能补0.5，条件分支不能作为无条件概率参与平均。候选失败如何影响最终交付须预登记；报告实际候选数、失败和成本，不能只选已知正确成员。新查询改变证据集时形成新候选批次，不混称相同输入。

候选校准形式可为 `p_cal = sigmoid(a + b * logit(p_raw))`；参数只能在待部署流程自身的开发/校准数据上学习，再用独立时间段检验。0/1端点的数值处理须明确版本化，原始概率永久保存。没有适用校准器就保持未校准，不自动使用论文中的固定系数。

校准改善概率映射，不能修复错误事实或错误目标；领域、模型、提示词、参照或聚合流程变化均检查失效。初版不在线自动拟合；公众专家预测只可用于基线及方法研究，不能代替本模型输出的校准样本。

## 7. 没有用户也能做的评估闭环

### 7.1 三类数据，三个不同结论

| 数据路径 | 用途 | 不能声称什么 |
|---|---|---|
| 固定/合成反例 | 状态、算术、推断规则和必要澄清测试 | 不能证明真实预测准确 |
| 公开已结局问题和历史证据 | 方法筛选、错误归因、成本与校准候选开发 | 当前模型可能记得结果，不能称独立前瞻效果 |
| 未结局公开问题，本地提前冻结 | 检验当前方法实际预测效果 | 不能外推到未覆盖领域或私人事实任务 |

用户数量不是任何一路的前置条件。开发阶段就同时建立未结局批次，在等待期间完成历史诊断。选择适用的7天数据题可以缩短首批等待，但不把原30天软件问题擅自改成7天，也不为了快出成绩只选快结局的问题。

### 7.2 资料封存与隔离

BenchmarkPacket须分别保存 `question_input`、`evidence_input`、`answer_oracle` 和 `resolution_labels`；模型上下文只接受白名单输入。标签、结局理由和他人预测默认不可见；共识增强组显式列为例外且只允许预测截止时已存在的共识。

历史回放记录真实获取时间和资料声称的历史时点，标记retrospective。当前抓到的旧网页不能回填为截止前入库，更不能放宽现有EvidenceService的前瞻资格规则。历史专用评估输入使用独立命名空间/合同，不伪装普通冻结实验。网页后续修订和模型训练记忆仍是限制。

按事件族和时间分割开发、选择、封存测试；同一事件更新、多期限问题及共享重大驱动的样本不能当独立重复。后续未来批次与调参批次分开。保存公开数据提交、哈希、许可、排除原因和模型版本。不能在看到结局后再选主指标或删题。

### 7.3 公平对手与消融

旧A/B/C协议保持原样。扩展实验另建合同，先声明资源上限与可见输入：

- A：适用的数据基线；不适用明确记缺失。
- B0：同模型一次直接预测，作为成本参照。
- B1：同模型允许必要追问和研究、相同总预算及工具权限的通用助手；回答由相同事前响应器提供，不能让B1缺少C获得的事实。端到端信息获取差异属于待测效果。
- C：候选预测架构。
- 诊断对照：固定相同证据包，逐项去掉参照、按缺口研究策略、推断审查、聚合或校准。研究策略的收益另在相同候选资料库/预算下测，不能拿固定证据包实验冒充检索效果。

不用一次运行所有组合。先检验单步候选与强基线，有收益再加下一步；版本选择与最终效果测试分离。即使多个模型组成候选系统，对照也应记录并匹配模型资源，不能把换了更强模型的收益归给流程。

### 7.4 准入与能力声明

主指标为共同已核验问题上的配对Brier差值；同时报告全登记覆盖、拒绝、失败、条件/方向交付、校准诊断、目标忠实度、成本与延迟。不能在小而容易的共同子集胜出后宣称整体更好。

优越性：候选相对强基线的预登记配对差值区间支持改善，且覆盖/错误/成本门槛通过。区间按事件族分组，重复模型采样还要报告运行变异。大量试验后选择获胜版本应在独立封存集重新检验。

非劣效：只适用于主要收益是成本/速度的变更，需事前锁定容忍界值；“差异不显著”不是通过。界值、最低覆盖、成本上限和样本量按开发先导数据与产品损失制定，不从论文抄一个通用样本量。当前这些数值未锁定，因此不得登记为已通过。

每次准入保存方法/代码版本、适用问题族、证据范围、测试批次、对手、误差区间、覆盖及限制。若只通过历史开发测试，展示“开发候选”；通过程序检查展示“流程可用”；获得足够前瞻证据后才在相应问题族声明效果。缺少优势时保留简单方案，不通过多拒绝或隐藏成本维护复杂架构。
