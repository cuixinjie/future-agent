## 使用与数据流

先确认完整预测问题，取得当前事件版本。`confirm` 本身会生成新版本。以下命令使用实际会话 ID 和版本替换占位符：

```powershell
# .env 中单独配置；SearXNG 实例必须开放 JSON 输出
# SEARCH_BASE_URL=http://127.0.0.1:8080
uv run --locked future-agent research plan <会话ID> --revision <当前版本> --subject "公开项目名" --focus "稳定版本发布"
uv run --locked future-agent research run <会话ID> --revision <当前版本> --subject "公开项目名" --focus "稳定版本发布"
uv run --locked future-agent research show <会话ID>
uv run --locked future-agent research cancel <会话ID> <研究ID>
# 确认工作进程已中断后，显式放弃旧执行；保留已预留预算和未知结果
uv run --locked future-agent research abandon <会话ID> <研究ID>
```

`plan/show/cancel/abandon` 不联网；`run` 会发送公开对象与主题到独立配置的搜索服务，并访问搜索结果中的网页。规划器不调用模型，不发送私人叙述、澄清答案或整个预测问题。`subject/focus` 应当由用户选择与目标相关、允许公开的关键词；程序拒绝邮箱、长数字串、URL、换行等明显敏感输入，但不能自动识别人名或所有私人信息。计划绑定事件版本、问题 ID、截止时点及 `search-rules-1.0`；不使用隐式跨版本缓存。

`CLI → ResearchService → SearchProvider / PageReader → EvidenceService → SQLite / SnapshotStore`。应用层声明端口，组合入口装配具体实现。合同通用基础移至 `domain/contracts.py`，原 `domain.events` 导入名称继续可用。领域层不导入网络、应用或数据库。

两条查询依次覆盖当前状态和反证，均完成后再读网页；按查询交错并优先不同主机，规范 URL 相同的候选仅抓取一次，全部候选来源记录保留。相同正文复用 T06 哈希去重规则。机制、案例和统计查询记录为按需暂缓，不凑页面数。规划器依赖用户提供的主题，不声称已具备模型语义相关性排序或完整研究能力。

搜索结果的标题、片段和日期线索先保存为 `candidate_only`；读取成功新增 `read_success`，失败新增 `fetch_failed`，不会覆盖候选。运行记录保存计划、每次尝试、候选和文档 ID、缺口与状态。正文记录同时保留原 URL 与 `final_url`。`date_hint` 只是未经核验的搜索字符串，不填入发布/修改日期；网页日期当前也不推断，未知保持 null。实际获取时间在正文处理完成后记录。

HTML 删除脚本、样式、导航等噪声，优先提取 main/article 文本；纯文本保留原始换行。T06 的 raw 快照在此表示提取后的正文文本，不是 HTTP 字节或完整 HTML 归档。固定提取规则不执行 JavaScript，不支持 PDF、登录页和动态渲染，也不能自动判断所有非空页面是否确为目标正文。引用仍按保存的 LF 规范化正文定位。

## 网络安全与失败

- 网页仅允许无用户信息的 HTTP(S) URL。每次实际请求，包括同域重定向，重新解析并检查全部 DNS 地址；本机、私网、链路本地、组播、保留及 IPv6 转换地址拒绝。连接固定到已检查 IP，Host 和 TLS 服务名保留原域名，证书验证开启，阻止 DNS 检查后重新解析绕过。
- 系统 DNS 解析放在可终止的短生命周期 Python 子进程中，超时后终止并回收；数字地址直接检查。Windows 子进程不创建可见控制台。该策略避免不可取消的系统 DNS 线程延迟退出，需要本地 Python 子进程运行权限。
- 搜索端点使用独立的显式配置通道，允许本地地址（包括 localhost），不跟随服务重定向。网页通道始终执行公网限制。两者都关闭环境代理，防止代理改变已检查的连接目标；当前不支持必须经过环境代理的网络环境。
- 每次尝试最多 30 秒，覆盖 DNS、连接、响应头、正文和跳转；最多 3 次跳转。只接受静态 text/html、text/plain；仍请求 identity，但兼容服务返回的单层、单成员 gzip。传输正文和解压正文分别限制为 2 MiB；分块解压按剩余额度限制输出，不先完整解压再检查。校验 gzip 结束标记、CRC 和长度，截断、损坏、尾随数据或多个成员返回 `invalid_response`；其他压缩算法或叠加编码仍返回 `unsupported_encoding`。解压和最终分块处理共享原请求截止时间，不因分块持续到达重置。文本编码按响应 charset，否则 UTF-8，解码失败明确记录。同步提取完成后复查截止，应用层也拒绝超时结果；同步解析和本地存储不是可抢占任务。
- 搜索要求 application/json，解析结构不合格、服务拒绝 JSON、HTTP 错误和超时均明确失败；远端错误正文不进入异常、日志或修复提示。搜索引擎不可用及非法候选保留标准缺口。没有候选是已成功搜索但研究不完整，与服务失败区分。

gzip 支持仅用于网页通道；搜索通道仍要求 identity，避免共享读取函数无意扩大独立搜索协议。已有压缩网页失败记录不改写，须在剩余预算允许时重新研究，或显式建立新会话/事件版本。Schema、提示词、方法和数据库版本均不变，无新增依赖、迁移或已封存实验快照变更。真实下载页复测及限制见 [验收记录](../archive/10-M1-M2真实接入验收.md)。

HTML 解析器拒绝的畸形正文按 `unsupported` 保存为 `fetch_failed`，保留候选和失败尝试，继续处理其余页面；不会因此将研究留在 `running` 或要求手动 abandon。解析器异常文本不进入持久化缺口或用户错误输出。

`completed` 表示计划内搜索与抓取成功，不代表证据充分或预测有效；存在缺口、资料不足、页面失败或预算耗尽为 `partial`，全部搜索失败为 `failed`，取消为 `cancelled`。`research run` 仅 completed 返回退出码 0，其余返回 2 并输出可检查的 JSON。存储或合同错误继续抛出，不变成成功；记录需检查并 abandon。无搜索配置时明确提示 `evidence import`，不创建演示结果、不自动切换离线资料。

## 共享预算与中断

创建会话时冻结 `MAX_SEARCH_QUERIES=8`、`MAX_PAGES=16`，与原有模型调用数、token 和总时间预算同属会话。改变环境变量不重置已有会话配额。每次搜索/网页重试都消费对应配额，重定向包含在一次页面尝试内并受跳转上限与同一超时约束。限流、临时错误、超时及网络错误最多重试两次；尊重 Retry-After，等待超出剩余时间或 30 秒时直接停止重试。

单次调用超时与共享总时间耗尽分别记录：仍有预算的单次超时保留 `timeout` 并按上述上限重试，超过单次上限的成功响应也拒绝使用；只有达到本次研究总截止时间或共享总时间上限才记录 `budget_exhausted` 并停止。每次尝试按实际耗时结算，不因重试重置预算。

模型调用、格式修复、搜索、抓取及重试使用同一个持久化 `consumed_seconds`，研究还计入本次规划后执行与本地存储的墙钟时间。调用开始前保存次数和保守时间预留，返回后替换为实际耗时；崩溃保留预留，不宣称请求严格执行一次。价格未知始终 null；T07 规划不额外调用模型，不新增独立模型预算。

研究状态单独保存在 `AnalysisSession.research_runs`，本阶段会话保持 M1 档案状态，不提前进入尚未实现的 ASSESSING。运行时阻止编辑、重新读取及并发研究；取消标志在调用前后和重试等待中检查，进行中的请求最多等到本次请求上限，不立即强行取消远端操作。中断后通过 show 检查，再 abandon；后续 run 创建新研究记录、只用剩余预算，不重写已有证据或假装原步骤已恢复。预测步骤的持久化恢复已由 [T10](12-T10冻结核验与恢复.md) 实现；本研究流程仍需显式 abandon 后创建新的研究运行。
