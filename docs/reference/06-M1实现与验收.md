## 1. 实际调用链

`cli.py` 是交互和组合入口，读取配置并注入 `EventService`、`ProtocolService`。应用层声明 `SessionRepository`、`ProtocolRepository` 和 `LLMProvider` 窄接口。领域层仅使用标准库和 Pydantic；SQLite/SQLAlchemy/Alembic、HTTPX 在基础设施层实现 I/O。人工演示入口 `examples/m1_offline.py` 也复用这些服务，没有另写业务规则。

正常路径：保存原文 → `READING` → 引用/结构校验 → `NEEDS_INPUT` → 保存答案或编辑档案 → 用户确认 → `STRUCTURED`。模型结果始终是待审查初稿，即使目标字段齐全也不自动确认。失败保留错误类别和调用尝试；不会生成空成功档案。

## 2. 首版数据契约

对象版本为 `schema_version=1.0`，Reader 提示词为 `reader-1.0`，数据库初始迁移为 `0001_m1`。三种版本独立管理。T01 没有历史业务数据，不需要业务数据转换；未知 Schema 或数据库迁移版本明确拒绝，不能静默清库。

- 原始输入和答案使用 UUID，保留 `raw`。`normalized` **仅**将 CRLF 和 CR 转成 LF，不去空格、不改变 Unicode、不删除 BOM。引用按 Python 字符串索引，范围为 `[start,end)`；切片必须与 quote 相同。输入文件使用 UTF-8，建议不带 BOM。
- M1 的 `Claim.text` 必须与 `quote` 相同，保留原句中的否定、条件和计划。Reader 还检查句子上下文边界，拒绝从“没有发布”截取“发布”。当前自动句边界为中文句号、问号、叹号、分号及换行（含 ASCII `!?;`），英文句点不自动拆分。
- Reader 陈述只能是 `user_reported`；M1 不存在外部证据，不能登记 `externally_supported`。观察、观点、意图和假设分开；对常见中文计划/观点词另做程序化检查。复杂语义仍需人工审查，不能把这些规则当成通用语义正确性保证。
- 模糊项引用陈述 ID；未知只描述当前状态，允许 `open/kept_unknown/answered`。用户明确保留的未知在重新读取时不会被模型自动补齐。未来结果属于 `ForecastQuestion`。
- 时间必须含时区，内部归一化 UTC；拒绝倒置窗口和晚于窗口起点的预测时点。问题、预测时点、窗口、结果类型、判定规则及来源规则缺失时保持 null，不能确认。M1 不包含概率字段。
- `EventRevision` 另存 UUID、事件版本、来源类型、创建时间及模型/提示词标识；预测问题绑定本次修订 ID。`confirm` 生成新版本并标记人工语义审查完成；修改后重新进入待确认状态，不覆盖旧版本。

## 3. 持久化与恢复

SQLite 保存会话、不可覆盖的事件版本和实验协议。创建请求可带幂等键：相同原文与预算返回已有会话；不同输入复用同键报冲突。写入使用会话版本比较，事件编辑还要求当前事件版本，避免并发覆盖。

首次需要数据库的命令通过 Alembic 创建真实表结构；重复迁移保留数据。发现已有未知表或未知迁移时拒绝操作。初始迁移没有无损降级，`downgrade` 明确拒绝删除历史；后续升级前应另存数据库备份，回退使用原备份，不能启动时重建数据库。初始迁移和版本化提示词随安装包分发。

进程中断时，已开始调用保留 `started` 和预算预留。普通 `resume` 显示状态，显式 `--retry-interrupted` 才将旧调用记为费用未知并继续。保存成功的读取不会被普通恢复重复调用；`--read` 显式读取新答案或重新生成初稿。

## 4. 模型适配器和预算

兼容协议：向用户配置的 `LLM_BASE_URL/chat/completions` 发送 `model/messages/max_tokens`。`text_json` 将 Schema 放入提示词，仅依靠本地校验；`json_schema` 显式请求 `response_format`（`strict=false`），仍做本地校验。不保证厂商支持严格 Schema 子集，不静默切换模式。`doctor --live` 用两个合成探测输入检查普通和当前结构化模式；失败类别通过真实返回或固定响应测试，诊断不刻意制造线上错误。

连接、读、写和连接池均有超时；单次请求上限60秒且不超过剩余时间。响应正文最多2 MiB，不跟随服务重定向。凭据只进入认证头，地址不得嵌入账号密码或查询参数；供应商错误正文、原始异常和非法模型输出不进入日志、修复提示词或持久化错误字段。模型通道允许显式配置本地地址，M1 没有任意网页抓取通道。

总超时由适配器内部的异步请求与取消机制执行，覆盖连接、响应头和正文，不依赖服务持续发送数据后才检查。应用层仍使用同步 `generate`；每次调用独立创建并关闭客户端与事件循环，证书配置在适配器初始化时准备，不跨事件循环复用连接。内部测试注入点由同步 `client` 改为异步 `transport`；应用端口、CLI、Schema、提示词及数据库格式不变，无需数据迁移。`doctor --live` 的两次探测均要求只返回 `{"ok":true}`，严格拒绝以整数或字符串代替布尔值。

身份和参数错误直接失败；限流、暂时性错误、超时和网络错误最多重试两次，遵守合法 `Retry-After`，超出剩余预算则停止。格式、引用或语义检查最多修复两次。所有调用共用会话累计预算，重新启动或修订不会重置：

| 配置 | 默认值 | 控制方式 |
|---|---:|---|
| `MAX_LLM_CALLS` | 12 | 每次尝试在 I/O 前保存并计入，包括修复及重试 |
| `MAX_RUN_SECONDS` | 600 | 持久化已消费时间；中断调用保留其超时预留 |
| `MAX_CONTEXT_CHARS` | 60000 | 适配器提交前检查完整提示词字符数 |
| `LLM_OUTPUT_TOKENS` | 4000 | 每次请求的输出额度 |
| `MAX_TOTAL_TOKENS` | 1000000 | 累计预算；调用前预留提示词 UTF-8 字节数加输出额度 |

服务返回完整用量时按实际 token 扣费记录；返回缺失或调用失败时保留保守额度，不填零。字节预留是预算近似，不是供应商的精确分词统计或账单保证。实际用量超过预算时不接纳结果并停止；价格未知始终保留 `cost=null`。真实模型的分词、费用及协议兼容性须按具体配置另行验证。

## 5. 发布预测模板和协议

模板生成唯一产品/通道的 `(T0,T0+30×24小时]` 二元问题。稳定版、预发布排除、去重、时间来源、完整记录才可判0，以及 pending/disputed/void 规则在模板中保留。M1 只保存目标和协议，不执行发布抓取、概率基线或结果评分。

协议保存选样来源与方法、入选及排除项目、发布和组件规则、官方来源、至少12个完整历史窗口的资格声明、Tc/T0、批次、A/B/C方法、模型/提示词版本、预算、指标和分析计划。历史记录资格在 M1 是用户声明，不代表已经抓取并核验；M2/M3 仍须检查实际快照。

程序验证 Tc≤T0、30天窗口、12个历史窗口、7天宽限期、三组唯一、B/C相同模型与最终输出额度、主要比较及预算完整。快照截止、B/C共享基础资料与答案但隔离C研究结论、概率缺失不补数值等政策为固定契约，不能用自由文本覆盖。协议在 Tc 前锁定并记录预登记时间，锁定后写入被拒绝。真实协议不能使用示例来源或夹具模型。

`examples/protocol.fixture.json` 的日期、名单、模型和来源都是明确的夹具，不是实际实验。锁定它只证明协议工具能运行。正式批次仍需选择真实名单、来源、服务、预算和日期，在后续预测前完成预登记。
