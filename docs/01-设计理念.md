# 设计理念

当前产品定位；与本分支代码对应。实现细节见[架构](02-架构文档.md)和[运行规则](03-设计文档.md)，未来工作统一见[开发计划](05-开发计划.md)。

## 产品要解决什么

用户描述一件事，由系统承担问题整理、公开资料研究和判断工作。交付应包含一个可理解、未来可核验的结论，以及依据、备选、未知和改变判断的条件。

系统不应让普通用户逐项填写内部研究表单，也不能通过无限追问拖延交付。普通会话最多一轮、三个必要问题，可以跳过。目标歧义确实影响研究时允许澄清；公开事实优先调查，系统默认与用户陈述分开。

## 如何表达判断

| 交付 | 含义 |
|---|---|
| 概率预测 | 有依据的主观概率，当前未经独立校准 |
| 方向判断 | 可以比较结果，但不支持数字 |
| 条件分析 | 不同条件分别判断，不强行合成为总体概率 |
| 未来探索 | 用户选择的可能性探索，不计作明确预测 |
| 无法判断 | 明确目标或依据缺口，不用泛化建议冒充预测 |

执行完成与形成预测分开。未知不自动意味着无法判断，也不能被补成0、0.5或“默认成功”。模型或网络故障是执行问题。

## 证据与方法边界

- 用户自述、外部材料、模型推断和系统假设分别保留来源。
- 搜索片段是线索，已读取正文才可成为精确引用；引用准确不等于事实可靠或推断正确。
- 普通判断由模型结合资料形成；通用历史参照估计、自动校准、训练和因果估计尚未实现。
- 搜索命中比例、角色意见一致、模拟频率或案例相似度不能当发生概率。
- 行动条件与既定路径分开，不能把相关性写成干预效果。
- 冻结预测不可覆盖，修订另存；不能利用已知结局优化后仍称独立评估。

## 当前适用范围

提供通用叙述入口，不代表拥有跨领域验证过的预测能力。首个计划中的效果验证领域是公开软件项目未来30天稳定发布；目前已有实验工具，真实前瞻实验尚未执行。

个人处境缺少关键私人事实时，应说明限制，不声称能够读取他人意图。模型和公开搜索的数据外发范围分别说明，私人信息不直接成为搜索词。

## 怎样证明有价值

评估同时看目标忠实度、证据相关性、预测误差、覆盖/拒绝/失败、交互负担和成本。与历史基线、同模型直接判断比较；更强的等预算可追问/搜索对照属于待实施工作。

没有用户也可用公开资料开发、自行登记未结局问题做前瞻核验，但历史回放仍有模型记忆和时间泄漏风险。借鉴专家实验用于选择候选方法，不代表本系统已达到论文成绩。
