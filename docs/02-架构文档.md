# 当前代码架构

本地单用户、前台顺序执行的模块化单体。技术栈为Python 3.12、Pydantic、HTTPX、SQLAlchemy/Alembic、SQLite和BeautifulSoup；依赖以[pyproject.toml](../pyproject.toml)及锁文件为准。没有独立API、Web界面、队列或后台工作者。

## 普通分析的数据流

1. 保存叙述；Reader仅提取原文，另存事件档案。
2. AssistanceService生成AnalysisPlan：主要目标、结果、窗口、核验规则、假设和公开查询。
3. 必要澄清消耗会话级额度；已用额度不会因恢复或补充而重置。
4. 用户授权查询后，ResearchService获取候选和正文快照；失败分别记录。
5. EvidenceReading提供精确引用、相关性解释、NumericBasis及未解决缺口。程序检查引用归属和原文位置。
6. 在研究完成后固定截止、保存最终事件版本并关联证据；EvidenceAssessment判断方法资格。
7. ForecastService调用模型形成结构化判断，领域验证器检查时间、结果对应及概率一致性。
8. 保存预测；报告只渲染保存数据。用户可导出、冻结、另存修订及手动核验。

目标澄清或实际补充信息触发重新分析。研究后回车跳过私人问题且输入/研究版本仍匹配时，保留阅读、引用、授权和预算继续判断，并记录未回答问题的影响。

## 状态与恢复

基础会话状态管理执行锁：CREATED、READING、FORECASTING、NEEDS_INPUT、STRUCTURED、FAILED。普通流程的细分阶段保存在AssistanceState：规划、澄清、研究、阅读、补充查询授权、就绪、完成或目标无法定义。

已有分析产物在输入版本有效时复用；执行中或中断步骤须处理后继续。模型尝试、研究尝试、预测步骤和预算持久化，重启不重置配额；未知费用不冒充零费用。

普通模式和高级人工模式共享服务，区别在自动整理/模型审查与人工确认。模型审查不会保存成人工签名。

## 存储与版本

会话、事件、评估、预测、冻结、核验和实验记录保存在SQLite；原始/规范化正文及导出文件位于批准的数据目录。预测引用绑定事件版本和证据快照，旧记录及冻结哈希不覆盖。

可读取格式、迁移头、方法/提示词版本统一见[数据与版本](reference/数据与版本.md)。时间、预算和安全细则见[运行规则](03-设计文档.md)。

## 实验与能力边界

现有实验器封存公开软件发布的A/B/C输入，运行历史发布频率基线、一次直接模型预测及指定版本的C组预测，并保存缺失、核验和配对评分。它不是任意题库的通用评估器，也不自动启动全部普通聊天流程。

普通参照仍主要是模型解释，发布频率计算仅在实验路径。可计算普通参照、结构化推断审查、强交互对照、聚合与校准均为[计划](05-开发计划.md)中的待实施能力。不存在独立CaseExtractor、知识图谱或自动训练模块。
