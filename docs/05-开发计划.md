## 1. 当前基线与第一版目标

2026-10-20 核对时，项目包含四份设计及开发文档、`AGENTS.md` 和 `CHANGELOG.md`；尚无业务代码、测试、依赖配置、锁文件或可运行命令，当前目录未初始化 Git。项目处于 M0 文档阶段，后续实施应重新核对实际状态。

实施更新（2026-10-20）：T01–T05 已实现，具备领域契约、原文引用校验、SQLite/Alembic、读取与澄清、版本编辑和确认、重启恢复，以及发布模板和协议锁定。已验证全新环境非编辑安装、打包、Ruff 及 M1 离线测试；真实模型服务与预测效果未验收。具体能力、契约与限制见[M1实现说明](06-M1实现与验收.md)及[使用说明](../README.md)。

第一版先完成两条相互关联的路径：

- 产品路径：输入叙述 → 读取与澄清 → 确认预测问题 → 研究证据 → 判断数据条件 → 情景或主观预测 → 报告。
- 核验路径：预登记实验 → 封存截止快照 → 保存并冻结预测 → 手动登记结果 → 比较基线、覆盖率和成本。

M1 至 M3 构成首个闭环。第一版不以拥有训练集、历史案例拟合或模型训练为启动条件；工具可用与预测有效分别验收。

## 2. 总体顺序与阶段依赖

```text
M0：核对设计与工程基线
  ↓
M1：工程基础 → 最小契约 → 持久化 → 读取与澄清 → 实验协议
  ↓
M2：导入与证据快照 → 检索与网页读取 → 数据条件评估
  ↓
M3：情景与主观预测 → 报告 → 冻结与核验 → A/B/C 工具闭环
  ↓
启动首批真实前瞻实验
  ├─ 等待结果期间可推进 M5：API → 单工作进程 → UI → 发布包
  └─ 取得评估依据后按需开展 M4：诊断 → 单项改进 → 独立后续验证
```

M4 为研究改进阶段，M5 为产品化阶段。编号保留原设计含义；M5 不依赖 M4 成功，也无需等待真实预测全部到期。实验期间必须冻结正在评估的方法；后续修复或研究另设版本，不能混入原批次。

先后依赖表示能力具备的顺序，不要求每个任务独立成为一个大型模块。每次实现只创建实际使用的目录、接口和依赖。

## 4. M2：建立可靠证据链

### T06：先做资料导入与证据快照

**状态**：已完成实现与离线验证（2026-10-20）；支持本地 JSON 资料导入、正文快照、引用、来源保留、内容去重和截止资格。网络检索与实验封存仍待后续任务，详见 [T06 实现说明](07-T06证据导入与快照.md)。

**依赖**：M1。

工作内容：

- 实现资料导入端口与固定网页夹具，定义 EvidenceDocument、EvidenceSpan 及其持久化关系。
- 保存正文快照、来源、获取状态、时间、哈希和可定位引用；明确引用对应哪份规范化文本。
- 实现日期资格、来源保留、URL 规范化与内容去重的当前必要规则。
- 区分正文已读、候选片段、获取失败和时点不明；历史发布日期不自动证明截止时点可见。

验收：引用能回到对应快照；失败和未知状态保留；截止时点后的资料不会进入实验输入。先用固定资料跑通真实内部流程，再引入网络变量。

### T07：搜索、网页读取与运行预算

**状态**：已完成实现与离线验证（2026-10-21）。规则规划、SearXNG、静态 HTML/纯文本读取、安全访问及共享持久化预算见 [T07 说明](08-T07搜索与网页读取.md)；已记录本地 SearXNG、真实搜索及部分外部网页/证据链路验收；上游搜索波动、研究部分完成及网页兼容范围见 [接入记录](10-M1-M2真实接入验收.md)。

**依赖**：T06。

工作内容：

- 实现 SearchPlanner、SearXNG 适配器、静态 HTML 与纯文本读取，并复用导入路径的证据契约。
- 查询优先覆盖当前状态和反证；检索不足时报告缺口，不凑页面数量。
- 限制请求超时、重试、响应大小、类型及重定向；验证 DNS 与每次跳转，阻止任意网页访问本机和私有网络。
- 用户显式配置的本地模型和搜索服务使用独立通道，不放宽网页抓取限制。
- 将搜索、页面、模型、总耗时、修复及重试纳入共享预算；最小化查询中的个人信息，日志统一脱敏。

验收：成功抓取、搜索不可用、正文失败、重复来源、越界 URL、取消和预算耗尽均有可检查行为；无网络时可显式采用导入资料，不能悄悄切换演示结果。

## 5. M3：预测、冻结、核验与比较

### T09：情景优先，再加入主观概率

**状态**：已实现，离线验证结果见 [T09说明](11-T09情景与主观预测.md)及变更日志。T10 已提供正式冻结与核验，真实模型预测质量未验收。

**依赖**：M2。

工作内容：

- 实现 scenario_only，输出方向、支持、反证、条件、观察信号，概率允许为空。
- 目标明确、开启数值估计且资料条件允许时，启用 llm_judgment，并标记未校准。
- 程序校验概率范围、结果定义及互斥穷尽分布的总和，按设计处理微小舍入误差；不静默裁剪非法数字。
- 保存事件、证据、方法、模型和提示词版本；以结构化预测作为报告的唯一事实与数值来源。
- 先用确定性报告模板输出可读报告；如后续加入模型润色，仍须验证其不创造事实、来源或概率。

验收：情景无概率正常完成；数值预测条件不满足时明确拒绝；报告与结构化产物一致，服务失败不产生空成功预测。

### T10：冻结、修订、手动核验与恢复

**状态**：已实现并通过实际运行的内部工具验收（2026-10-22），包含真实 SQLite/Alembic、文件、跨进程 CLI 和子进程直接退出后的恢复；外部模型边界使用夹具，不宣称真实预测效果已验收。命令、契约及迁移见 [T10说明](12-T10冻结核验与恢复.md)。

**依赖**：T09。

工作内容：

- 冻结预测的目标、事件版本、证据快照、截止时点、方法版本和计算参数。
- 修订另存并关联旧预测；冻结内容不可原位覆盖。
- 实现 ResolutionService，登记结果证据、核验人、理由及 pending/resolved/disputed/void 历史。
- 步骤完成即保存，恢复前检查输入版本、取消标记和已完成产物，避免重复创建预测。
- 外部调用结果不明时保留尝试记录和可能重复费用，不承诺严格执行一次。

验收：冻结后修改被拒绝；修订和核验状态变化留痕；取消、崩溃恢复不会覆盖历史或重复生成已有预测；未决不当作负例。

### T11：A/B/C 运行与评分工具

**依赖**：T05、T10。

工作内容：

- 实现实验专用 release_frequency_baseline，验证完整历史窗口、稳定发布排除规则、事件去重及时间边界。
- 实现同模型直接预测组 B、完整流程组 C；按协议共享基础资料与澄清答案，隔离 C 的研究结论。
- 支持截止快照封存、输入哈希、共同提交期限和迟交判定；实际执行的模型、提示词和方法版本须符合协议。
- 为全部预登记条目保存 EvaluationEntry，包括失败、拒绝、迟交和缺失原因；实验中的取消或崩溃也不得使条目消失。
- 实现有效 resolved 结果的 Brier 评分、配对差异、共同子集、覆盖率、情景输出率、核验状态及成本报告；价格未知留空。
- 用固定夹具运行真实领域、存储和评分逻辑，外部边界可替换；不以模拟结果宣称预测有效。

**M3 工具完成门槛**：从协议、快照、A/B/C 预测到冻结、手动核验、评分的离线闭环可运行；缺失和关键失败路径可验证。没有概率的情景不补成 0.5，历史记录不足不补成 0。

### T12：首批真实前瞻实验

**依赖**：T11 验收通过，真实名单、服务、预算和协议已落实。

实施顺序：

1. 依据预先说明的选样方式确定项目与排除原因，冻结具体发布规则及协议。
2. 在截止时点前取得并封存各组允许使用的输入；完成真实服务诊断，按预算运行。
3. 在共同冻结时点前提交首次预测，保留全部条目与失败原因。
4. 等待观察窗口结束，按统一核验规则登记结果；未到期保持 pending。
5. 报告配对误差、覆盖率、证据问题和成本，不把少量命中或共同子集优势当作普遍有效。

真实实验的观察窗口具有不可压缩的日历等待时间。工具验收无需等待到期；准确性评估必须等待真实结果。试运行用于发现流程问题，后续独立批次才用于检验调整后的方法。

## 7. M4：根据证据选择改进

**进入条件**：已有足以支持问题诊断的核验与评估记录；不预设固定样本量足以证明有效。

| 观察到的问题 | 优先行动 |
|---|---|
| 关键当前事实未被找到 | 检查检索规划、来源选择与正文读取 |
| 找到了资料但理解或引用错误 | 改进抽取、提示词、引用及时间校验 |
| 证据正确但概率存在稳定偏差 | 在具备合格数据后评估校准方法 |
| 存在完整、可比的事件样本 | 按独立任务评估通用 reference_class |
| 存在连续且口径一致的数据 | 按独立任务比较朴素基线和 time_series |
| 案例可能提供额外信息 | 先做资格与逐项比较，再预登记增量实验 |
| 完整流程没有明确收益 | 保留不确定或未改善结论，优先简化无收益步骤 |

每次只选一个可验证的瓶颈，明确新增成本，生成新方法版本，并在未参与调优的后续批次验证。同一事件及更新不得跨调优与测试集合泄露。记录增多不自动触发调权、校准或训练。

## 8. 防止开发失序的执行约定

### 8.1 按用户行为拆任务

T01 至 T16 是能力依赖清单，可以继续拆成较小任务；单个任务必须有一个可演示结果。不要把“完成所有领域模型”“完成整个数据库”“完成所有智能体”作为长期独立工程，避免最后才发现接不起来。

每次实施先写明目标与阶段、现有数据流、修改范围、不涉及范围、兼容影响、验收方式和未确定项。完成当前目标后再推进下一项，不顺带整理无关代码。

### 8.2 保持唯一规则来源

```text
CLI / API → 应用服务 → 领域对象与规则
基础设施实现 → 应用层端口 / 领域对象
组合入口 → 构造具体实现并注入
UI → API
```

程序拥有状态、资格、预算、重试、数值与评分规则。模型负责限定任务中的结构化生成，不能自行改变目标、恢复预算或决定数据已核实。普通内部函数无需都包装为接口，不引入通用插件框架。

### 8.3 按当前任务安装依赖

- M1 引入契约、持久化、模型接入及必要检查依赖。
- M2 再增加正文提取等检索依赖；SearXNG 作为独立服务单独验证。
- M3 按实际计算需求引入数值依赖，不提前引入学习框架。
- M5 再引入 FastAPI、Streamlit 及启动所需依赖。
- 向量数据库、知识图谱、Redis、分布式队列、群体仿真、自动训练与长期监测均暂缓。

### 8.4 完成一项再记录一项

每项完成后记录实际改动、实际检查和限制；重要行为、契约、依赖、安全或方法变化同步 `CHANGELOG.md` 的 `Unreleased`。只有验收通过后才标记完成。不得把本计划的任务清单当成实现状态。

## 9. 验证与交付要求

工程初始化后，按风险运行相关检查；以下检查入口已在 T01 配置，各次变更仍须报告实际执行结果：

```text
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest <本次相关测试路径>
```

验证分为三类，报告时分别说明：

| 类别 | 验证内容 | 能支持的结论 |
|---|---|---|
| 程序正确性 | 领域边界、引用、版本、状态、预算、持久化、恢复、评分 | 内部行为符合规则 |
| 服务兼容性 | 实际模型、搜索和网页通道的协议、错误及超时 | 已测配置在本次环境可用 |
| 预测效果 | 截止快照、前瞻冻结、真实核验、基线配对、覆盖率与成本 | 在特定样本及方法版本下的效果与限制 |

默认开发验证采用固定夹具，不产生付费调用。真实接入任务按已确定的服务与预算执行。纯文档修改检查设计一致性、相对链接及状态表述，不新增代码测试。
