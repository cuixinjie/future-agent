## 1. 当前基线与版本边界

普通路径：叙述 → Reader 原文提取 → 系统目标/研究计划 → 至多一轮澄清 → 有界研究与精确引用 → 依据评估 → 主判断或明确限制 → 报告 → 冻结及后续手动核验。

高级路径：`chat --manual` 与分步 CLI 保留逐项确认、人工引用审查及显式数值许可。普通模式不再要求用户承担这些内部工作；模型审查记录其来源，不冒充人工确认。

实验路径：旧 T11 封存、A/B/C、共同核验及评分保持原版本。新普通方法 `judgment-2.0` 已有独立Schema 2.0实验适配，禁止混入锁定 `judgment-1.0` 的旧协议。

|---|---|---|

| M2 / T06–T08 | 导入、快照、检索、安全抓取、预算及数据条件评估已实现 | [T06](reference/07-T06证据导入与快照.md)、[T07](reference/08-T07搜索与网页读取.md)、[T08](reference/09-T08数据条件评估.md) |

## 2. 当前推进顺序

```text
已有 M1 → M2 → M3 工具闭环 + M5 CLI
  → R01–R05 普通主线改造（已实现）
  → R06-A 真实服务与语义验收
  → R06-B 新方法实验适配及独立协议
  → T12 / R06-C 真实前瞻提交、冻结、到期核验及比较
       ├─ 等待期间可独立推进 M5 Web（T13–T16）
       └─ 有评估依据后按需开展 M4，并用后续独立批次验证
```

M5 不依赖 M4 成功，也无需等待真实预测全部到期。旧锁定实验可按旧版本独立运行；它不能完成新版 R06-C。真实结果的日历等待不能用离线夹具或回看结果替代。

## 3. 普通主线 R01–R05：已实现范围

| 任务 | 可验收行为 | 状态与限制 |
|---|---|---|
| R01 | Schema 2.0 区分概率、方向、条件、探索与无法判断；校验结果、排序及概率一致性 | 已实现；执行完成与预测交付分开 |
| R02 | 系统拟定目标与显式假设；整会话一轮最多三问；跳过/恢复不重置；固定截止及窗口保护 | 已实现；相对窗口预留剩余生成预算加 1 秒，准确起止写入报告 |
| R03 | 目标驱动查询、至多两轮研究、自动精确引用、授权及共享预算 | 已实现；首轮最多 2 条，第二轮最多 2 条已授权查询或另行授权的新查询，网页兼容能力仍有限 |
| R04 | 参照起点、本次差异、未知影响、数值依据评估及模型审查来源 | 已实现；不含通用统计拟合、因果估计或校准 |
| R05 | `chat` 普通入口、`--manual` 高级入口、会话恢复、报告与历史兼容 | 已实现；复用应用服务、持久化步骤及预算 |

版本与代码事实以改造决策及对应契约为准，不另复制一套参数表。R01–R05 的程序验收不能将 R06 标为完成。

普通流程追问改进：关键目标歧义可在研究前澄清，研究后关键私人事实可使用剩余额度；Reader内部问题不作为普通模式待办；期限按问题提出显式假设。离线测试验证状态边界，真实模型的目标忠实度与追问质量仍需R06-A验收。

## 4. 下一阶段：R06 与 T12

### R06-A：真实服务与语义验收（已执行部分，通道与语义验收仍受限）

依赖：可用的模型和搜索配置、明确外发范围及实际调用预算。

2026-10-29 独立试运行已取得真实网页正文、引用和报告，并抽查部分引用相关性；搜索引擎不可用及配额耗尽使研究仍为部分完成，更多语义样本和真实场景仍待验收。详见 [复验记录](reference/15-R06真实链路复验-2026-10-29.md)。

- 分别验证模型、搜索、正文通道，再执行普通 `chat` 及恢复路径。
- 抽查目标忠实度、首次追问必要性、查询覆盖、精确引用的相关性、参照合理性及结论区分力。
- 记录目标误解、重复/无价值追问、人工输入次数、所有交付类型、失败原因、调用/token/耗时及未知费用。
- 覆盖不联网、搜索失败、正文失败、条件未知、数字依据不足、固定窗口已开始及中断恢复；不把服务故障写成世界不可判断。

验收产物：带运行日期、配置标识与脱敏证据的记录。旧接入记录保留原日期和结论，不改写成新版验收通过。

### R06-B：新版独立实验适配（已实现，固定夹具验收）

独立Schema 2.0协议、spec快照封存、新版执行分支及交付覆盖已实现，旧实验保留原版本。实现与真实验收限制见[R06记录](reference/14-R06验收与新版实验.md)。真实独立前瞻运行仍属于R06-C。

依赖：明确新版待比较的方法、共享输入与人工负担指标；按契约变更检查兼容性和迁移。

- 为 `judgment-2.0` 新增明确的协议/执行适配，保留旧 T11 版本及冻结哈希。
- 在结果未知时预登记选样、Tc/T0、模型/提示词/方法、预算、核验来源、首次及更新预测、缺失与拒绝处理。
- 数值预测使用适用评分；方向、条件、探索和无法判断另报覆盖，不填成 0、0.5 或任意数字。
- 比较基线、同模型直接预测和新版流程，说明额外计算预算的差异；预登记引用错误、人工负担和成本指标。

验收：固定夹具验证真实内部封存、全条目登记、版本隔离、时点及评分边界；旧锁定协议仍按旧版本执行。适配通过不代表真实效果通过。

### T12 / R06-C：真实前瞻实验（待执行）

旧方法 T12 依赖 T11、真实协议/名单/服务/预算。新版 R06-C 还依赖 R06-B，不能直接复用旧 C 组版本。

1. 按预登记来源确定项目和排除原因，锁定发布定义、官方来源及版本。
2. 在 Tc 前取得并封存允许输入，在共同提交期限前保存并冻结首次预测。
3. 保留全部项目×组条目及缺失、拒绝、迟交、取消和失败原因，不删除难题。
4. 等待完整观察窗口，按规则追加核验；未到期保持 pending，争议及作废分别记录。
5. 报告配对误差、共同子集、全样本覆盖和成本，说明样本及相关性限制。

首个效果问题仍为公开软件项目未来 30 天稳定版本发布。试运行用于定位问题，调优后的方法必须在后续独立批次评估，不能回填原批次或声称少量命中证明通用有效。

## 5. M5：产品入口与 Web 后续

### 5.1 交互式 CLI（已实施）

S2-01 会话导航、S2-02 预测引导、S2-03 预算/中断/恢复、S2-04 报告/历史/说明均已实现。初版人工流程由 `chat --manual` 保留；普通流程已由 R05 改造。命令和实际使用方式统一维护在 [交互式 CLI](guides/交互式CLI.md)，不在计划中重复操作手册。

当前为本地前台顺序执行，复用应用服务；不依赖 FastAPI、Streamlit 或工作者租约。PDF/Word、全屏 TUI、多用户、后台自主监测和会话删除不属于已实现范围。

### 5.2 Web 方案（T13–T16，待实施）

| 顺序 | 任务 | 交付及验收 |
|---|---|---|
| T13 | FastAPI 入口 | 调用应用服务；校验输入、幂等、版本冲突及状态错误，健康检查脱敏，默认监听本机 |
| T14 | 数据库任务与单工作进程 | 领取、租约、心跳、步骤保存、取消与恢复；任务不只在请求内存中 |

| T16 | 启动、隐私与发布包 | 统一启停、安全导出及会话删除；保护共享文件和路径边界，落实许可证及干净安装验证 |

进入条件为共享应用服务稳定和工具闭环可用。Web 复用新版普通主线，不能重新要求用户填写全部内部研究字段。仅在实施相应任务时安装 API/UI 依赖。

## 6. M4：按评估选择改进

研究质量与预测评估的设计、授权及版本边界见 [优化决策](decisions/研究质量与预测评估优化.md)。动态补充查询、正文词项选择与模型证据检查已实现，真实语义质量待验；新版独立实验适配已有固定夹具验收，不能声称准确率已提升。

有足够记录支持诊断后，每次只选一个瓶颈：检索遗漏、证据误读、参照缺失、概率偏差或任务边界。完整可比事件样本才评估通用 `reference_class`；口径一致的连续数据才比较朴素基线和 `time_series`；案例、校准或训练须证明额外价值。

每次实质变化生成新方法版本，在未参与调优的后续批次验证；事件及更新不跨调优和测试集合泄露。无改善则保留结论，简化无收益步骤，不因记录增多自动训练。

## 7. 执行与交付门槛

一次变更围绕一个可演示结果，沿用模块化单体与当前目录；只创建实际使用的文件和依赖。程序控制状态、资格、数值、预算、时点和重试，模型不能改变这些规则。

按风险执行检查：纯文档核对链接和状态；业务边界覆盖正常及关键失败；持久化/恢复覆盖旧数据、版本、取消与幂等。默认使用显式外部夹具，不产生付费调用。只报告实际执行的命令；工具、服务、效果分开说明。重要变化更新 `CHANGELOG.md` 的 `Unreleased`。

待落实：真实调用预算与服务复核、实验名单及发布规则、Tc/T0 和独立批次；新版协议适配已通过固定夹具验收。用户已授权将当前实现作为公开 Alpha 实验版发布至新 GitHub 仓库，已知限制随版本说明保留；本次不授予开源许可证，后续授权另行决定。源码发布不等于 R06-A 全部通过，也不等于已运行前瞻实验。
