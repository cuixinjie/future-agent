# M5 方案二：交互式 CLI 预测助手

日期：2026-10-27。已包含 S2-01–S2-04 的本地前台终端入口及 R01–R05 普通预测主线；Web 方案 T13–T16 仍独立保留。程序验收采用固定外部夹具和真实本地持久化，不代表真实服务可用或预测准确。

## 1. 启动

在项目根目录执行：

```powershell
uv sync --locked
uv run --locked future-agent doctor
uv run --locked future-agent chat
```

首次使用先复制 `.env.example` 为 `.env`，配置 `LLM_BASE_URL`、`LLM_MODEL` 和必要的密钥。搜索单独配置 `SEARCH_BASE_URL`；不配置搜索时保留无检索限制，按已有用户信息与明确假设判断，不虚构网页证据。`doctor` 默认不联网；真实模型诊断使用 `doctor --live`，会消耗调用。

首次启动引导输入叙述；已有会话时提供编号列表，可新建或继续。也可以直接打开指定会话：

启动页显示模式和数据发送提示；输入区以 `>` 标识，完整操作列表可随时通过 `/help` 查看。状态和报告使用独立标题，方便在终端输出中定位。

```powershell
uv run --locked future-agent chat --resume <会话ID>
# 使用独立数据目录时，后续继续使用同一目录和数据库配置
uv run --locked future-agent --no-env --data-dir data/my-analysis chat
```

自定义数据库仍须位于批准的 `DATA_DIR` 内。配置未完成时可保存叙述和查看历史，模型操作明确报错，不会自动生成演示结果。

## 2. 一次分析

### 2.1 默认普通模式

1. 输入叙述并允许在会话预算内使用模型。Reader整理原文，系统另拟目标、期限、结果定义和研究计划；默认与假设会展示。
2. 必要时一次提出最多三个会改变判断的问题，可一起回答或直接回车保留未知。整个普通会话只允许这一轮，恢复和补充不重置。
3. 配置搜索时，展示最多四条初始公开查询并请求授权。未授权则基于已有资料继续评估。首轮最多两条；仍有重要缺口时至多再研究一次，模型新提出的查询会单独展示并请求授权，拒绝则继续已有资料。用户无需挑正文或填写相关性。
4. 系统自动提取正文精确引用，检查出处和偏移，并保存模型审查来源、资料限制及未知影响。不会将网页片段冒充已读正文。
5. 研究完成后固定证据截止。相对目标的窗口起点安排在剩余生成预算加1秒之后，通常有数分钟准备间隔；准确时间写入报告。固定绝对窗口不静默移动，提交超过起点拒绝作为事前预测。
6. 报告先展示交付类型、当前判断、参照及调整、未知与改判条件。有依据时给未校准概率；也可能交付方向判断、条件分析、探索或无法判断，后几类不冒充数值预测。
7. `/save`保存，`/freeze`冻结，未来`/resolve`登记实际结果。目标无法定义时原因保存在会话状态，尚未生成Forecast，不强制导出假报告。

代码路径为 `chat → AssistanceService → 既有应用服务`。普通阶段保存在AssistanceState，恢复只展示现状，明确继续后复用有效产物。详细版本、预算和实现限制见[改造决策](../decisions/预测主线改造.md)。

使用原人工路径：

```powershell
uv run --locked future-agent chat --manual
uv run --locked future-agent chat --manual --resume <会话ID>
```

### 2.2 高级人工模式

1. 描述事情，选择是否调用模型读取。普通输入为单行，较长叙述可以分多次补充；对话不执行任意 shell 命令。
2. 阅读分层档案：陈述保留自述属性；参与者、时间线、约束、计划、模糊项和未知单独展示。每轮既有澄清问题最多三个。直接输入文字补充或纠正信息，答案先保存，再选择是否重新调用 Reader；`/unknown` 按编号明确保留未知。
3. `/continue` 引导填写完整目标，或用 `/target` 逐项修改问题、结果类型、证据截止、窗口和判定规则/来源。回车保留原值；填写含时区的 ISO 时间。随后明确确认档案。确认产生新事件版本。
4. 选择公开检索或明确不检索。检索只发送用户明确填写的公开对象和主题；失败、部分完成和缺口如实展示。模型服务和网页通道的安全规则沿用既有实现。
5. 审查有资格的已读正文；从正文粘贴唯一的精确片段，选择当前状态/反证/机制用途并填写相关性理由和审查人。搜索片段、失败来源、截止后材料及重复来源不能冒充合格正文。填写最多三个阻断数值判断的关键问题，可补充资料限制。
6. 默认生成条件情景。申请主观概率时仍由 T08/T09 判定资格；资格不足会说明原因，必须明确同意才能改为情景，未同意时不调用预测。结果定义和互斥穷尽/独立关系须人工审查，再确认模型调用。
7. 查看报告，按需 `/save` 保存、`/freeze` 冻结，之后 `/resolve` 追加实际结果核验。

证据截止不是页面发布日期：获取时间和本地入库时间也必须不晚于截止。若计划现场检索，请为采集预留时间，截止应覆盖采集结束且不晚于窗口起点。已经过去的截止不会因本次检索而自动延后；资料被排除时可以保留缺口生成情景，或明确修订目标重新开展分析。旧版本的资料和预测不会自动迁移到新事件版本。

## 3. 会话操作

| 命令 | 行为 |
|---|---|
| `/continue` | 从已保存状态继续引导；有执行中/中断步骤时先要求处理 |
| `/status` | 显示目标、事件版本、阶段、未知、研究缺口及剩余预算 |
| `/read`、`/answer`、`/unknown`、`/target` | 读取、补充、保留未知及逐项修订目标 |
| `/research`、`/forecast` | 普通模式继续自动分析；高级模式分别启动研究或人工审查后预测 |
| `/report`、`/save` | 查看、保存当前选中的预测；默认选最近的已保存预测 |
| `/history` | 按编号选择历史预测；旧事件版本报告明确提示 |
| `/freeze` | 冻结草稿，或选择旧冻结预测并填写修订理由；已有冻结不改写 |
| `/resolve` | 展示核验历史并追加 pending/resolved/disputed/void |
| `/retry` | 检查中断状态，明确接受费用未知和可能重复费用后恢复 |
| `/cancel` | 显式取消中断步骤，保留产物、尝试及已消耗预算 |
| `/new`、`/select`、`/exit`、`/help` | 新建、选择会话、退出及帮助 |

支持“继续、状态、报告、保存、退出、帮助”这些有限自然语言操作，其他文字保存为叙述或补充。不会由模型自行决定实际操作、数值许可或人工确认。任意输入提示下可用斜线命令；`/status`、`/report`、`/save`、`/help` 完成后返回原输入，其余命令切换操作，尚未提交的表单需要重新填写。终端展示过滤控制字符，外部文本不作为终端指令。

冻结时可预先指定允许提前核验的发生结果。`resolved` 引导输入实际结果、必要的发生时间、结果来源、已读正文和精确引用，来源按冻结规则人工选择；程序复核结果、窗口及证据。完整窗口未结束时，不得把暂未发生登记成负例。其他核验状态不带结果，也不作为评分。后续补充和修订不覆盖旧预测；目标、窗口、规则改变时不能关联为同一目标的修订，须独立冻结。实验仍使用 T11 专用命令，普通聊天不自动登记为独立实验样本。

## 4. 持久化、中断和预算

普通路径由 `chat.py → AssistanceService → Event/Evidence/Research/Assessment/ForecastService → 领域规则及端口` 编排；报告、冻结和核验继续调用原应用服务，高级人工入口直接复用各分步服务。`cli.py` 负责装配模型、搜索、网页、SQLite 和文件适配器。交互层不访问 ORM 或具体模型。无新增依赖或表，数据库迁移头仍为 `0006_evaluation`。会话Schema升至1.5；普通预测Spec/Draft/Forecast为2.0，提示词forecast-2.0、方法judgment-2.0；旧1.0预测、Reader与旧实验入口保留。

恢复会话只读取原状态，不默认调用模型。读取中断需要明确恢复；预测按已保存步骤 ID 恢复，配置和输入版本仍由现有服务复核，已完成步骤返回原产物。中断研究明确终止旧运行，再由用户另开研究，不重置累计预算。

Ctrl+C 返回 130，保留已完成产物和已经登记的尝试；进程崩溃后也按持久化状态恢复。结果未知的调用保留费用未知，重试可能重复计费；未发生的本地表单输入不代表步骤完成。终端按前台顺序执行，运行请求时不能同时接收斜线命令；此时用 Ctrl+C 中断，再打开会话检查或取消。没有后台任务、租约、实时流式 token 展示或任意进程管理。

预算由原服务执行，不依赖交互文字。`/status` 展示剩余调用、token、时间、搜索和页面配额；价格未配置，不显示虚构金额。预算耗尽或模型故障不会保存空成功预测。此前存在的报告仍可查看和保存。

## 5. 导出合同与文件边界

`/save` 每次创建 `DATA_DIR/reports/<随机ID>/`，包含 UTF-8 的 `report.md`、`report.json` 及成功写入后的 `COMPLETE` 标记，显示两个文件的绝对路径。再次保存、冻结后保存和修订后保存均另建目录；同名目录/文件拒绝覆盖，解析后的路径不得越出批准目录，包括目录链接。中途写入失败不报告成功；无 `COMPLETE` 的目录表示未完整保存，保留以便检查，不自动清理数据。

Markdown 来自既有确定性报告。JSON 是 `kind=forecast_report` 的**导出投影**：新版判断为schema_version=1.1，旧预测保留1.0，不是可重新导入的完整 Forecast：保存预测/会话/事件版本标识、目标、结果定义、方法/模型/提示词版本、校准性质、原始结构化判断、校验概率、舍入说明、未知、限制、缺口、已审查精确引用及来源时间/哈希；冻结时附冻结时间、完整原始预测哈希与前驱/理由。该哈希验证的是数据库中的完整冻结对象，不是裁剪后的导出 JSON。

不附带完整会话原文、答案列表、整页网页缓存、文件路径及服务配置/密钥。但问题、未知、判断和引用本身仍可能包含私人信息，应按需保管；这不是匿名化或自动脱敏工具。缺失概率保留 JSON `null`。PDF/Word、会话删除、Web、多用户和主动监测不在这次交付范围内。
