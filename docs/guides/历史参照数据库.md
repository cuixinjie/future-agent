# 历史参照数据库与普通预测

这是首版开发功能。软件发布历史与公开预测题分别保存，软件发布尚无合格真实数据集或独立效果成绩；体育/政治另有小样本定性案例，见下文。

## 启用与使用

默认关闭。设置 `HISTORICAL_REFERENCE_ENABLED=true` 后，普通 CLI chat 和本地 Web 复用相同服务：目标规划产生候选映射，研究前查询，最终事件生成后重新检查，参照绑定随预测、步骤、冻结和导出保存。无匹配数据照常研究；失败单独记录，不填默认概率。不增加模型调用。

```powershell
uv run --locked future-agent reference schema dataset
uv run --locked future-agent reference schema plan
uv run --locked future-agent reference schema questions
uv run --locked future-agent reference collect numpy/numpy --product NumPy --channel stable --version pilot-1
uv run --locked future-agent reference import reviewed-dataset.json
uv run --locked future-agent reference import-questions diagnostic-bundle.json
uv run --locked future-agent reference question-inputs <bundle-id> --split development
uv run --locked future-agent reference check plan.json --cutoff <UTC时间> --start <UTC时间> --end <UTC时间>
```

命令共用全局 `--data-dir`，建议采集先使用独立开发目录。`collect` 请求固定 GitHub Releases 接口，复用公网 DNS 固定、TLS、正文大小和请求超时限制；最多200请求、30分钟、100MB，不重试。仅按 published_at 提取，不使用普通 Git tags。完整分页不证明产品映射或发布渠道完整，采集结果始终 `unreviewed`、`complete=false`。成功页面快照和失败状态保存在 DATA_DIR/reference-acquisitions 中；失败不导入伪完整数据集，重新采集另建批次。

采集不会代替人工审查。审查者须核对产品、通道、稳定版资格、分页、至少360天覆盖和原文依据，再另建数据集ID/版本，填写实际审查者及完整性依据；保留真实获取时间。AI不得把自己写成人工审查者。修改数据集后重算清单哈希：对Pydantic `ReleaseDataset.model_dump(mode="json", exclude={"manifest_hash"})` 调用共享 `fingerprint`；时间规范为UTC。导入再次验证哈希和引文，正文写入成功后记录实际入库时间，并重新生成包含该时间的清单哈希。同ID同内容幂等返回原数据，同ID或同产品/通道/版本不同内容拒绝覆盖。

## 统计与时间边界

仅匹配明确的同产品/通道 GitHub 稳定发布、相对30天、二元、既定路径目标，定义版本 `github-stable-release-30d-1.0`。模型映射是候选，不是人工确认。未审查、错产品/通道/期限、绝对窗口、历史不完整、截止后获取/入库、资格冲突均不能计算。

程序复用 `release-frequency-1.0`，保存12个连续30天窗口标签、k/12、原始频率、资料来源、数据集哈希、排除原因及限制。历史锚点使用已封存历史覆盖终点，不能用资料没有覆盖的时间填负例；锚点至目标起点最多3601秒，规则锁定在 `release-reference-1.0`。因此旧库不会无限期自动适用，超过时间需要重新采集、审查和发布。未来按不同时间间隔适配须另建方法，不能悄悄放宽。

参照不自动授予最终数字资格，原 NumericBasis 及正文/自述门槛继续有效。报告并列显示程序频率和模型判断，无总体概率时也可显示历史频率；频率不等于未来概率。当前不支持参照单独作为数值依据、自动补齐采集缺口或通用案例概率。

### 贝叶斯发布参照（2026-11-04）

新参照 `release-reference-1.2` 只对通过全部准入检查的12个窗口计算。令发生窗口数为 k、n=12：固定先验 p~Beta(1,1)，二项似然与先验相乘得到后验 Beta(k+1,n-k+1)，下一同机制窗口的后验预测概率为 `(k+1)/(n+2)`。例如8/12对应9/14=64.3%，0/12对应1/14，12/12对应13/14。原始频率仍保留，旧实验A组仍使用k/12。

固定均匀先验是预先声明的开发候选，目的是在有限样本下避免机械输出0或1；不是经验拟合的最优先验。它等价于给发生和未发生各加一个伪计数，但不会把伪计数加入真实标签、原始分子或分母。公式依据：[Berkeley Beta–Binomial推导](https://stat238.berkeley.edu/spring-2026/lectureeight238spring2026/)、[Lancaster后验预测推导](https://lancaster.ac.uk/~prendivs/accessible/math331/lectures.tex/Ch3.S1.html)。

`bayesian_estimate` 保存算法 `beta-binomial-uniform-1.0`、先验、真实计数、后验参数及预测概率，领域校验拒绝不一致、非有限值和非法类型；外层检查计数与历史标签一致。未匹配、失败、未审查和历史不完整均不生成该字段，不能只靠先验输出50%。报告、Web与JSON导出分别标明历史频率、贝叶斯统计参照和最终主观判断；报告不重新推断概率。

该估计假设窗口在给定发生率下独立且未来机制稳定；相邻窗口相关、发布政策改变或距上次发布的时长都可能影响适用性。目前未拟合时间模型、未计算可信区间、未独立校准，也未证明比原始频率准确。参照仍受开发开关控制，正式真实数据准入仍为0，不自动修改审查标记。验证改善须另行冻结方法，在独立前瞻样本上与原频率、同模型直接判断及等预算对照比较Brier、覆盖和成本，不能用评测结局反过来调整本次先验。

新参照对应方法/提示词 `judgment-reference-1.1` / `forecast-reference-1.1`；旧参照1.0/1.1仍使用旧方法及旧提示词。Forecast/步骤/导出容器版本不变，新增可选字段缺省省略，读取旧记录和恢复旧步骤不补算后验，旧冻结哈希保留。没有新迁移或依赖；旧程序无法读取新方法/字段，回退须恢复升级前完整DATA_DIR备份。

## 题库与标签

`DiagnosticBundle` 只接受最多50题的显式静态包，必须保留来源提交、许可、归属、选择规则、问题/规则版本、截止、窗口和事件族切分；每题均须登记结果，包括未决、争议和作废。同事件族不能跨切分。

白名单投影仅给问题、规则、时点及人工审查过的事前文本，不给结果标签、结果解释、许可文件名或结果时间。未审查材料仅用于问题解析诊断；人工声明历史可见性不证明文本完全没有答案暗示，仍需独立抽查。关闭实时搜索，保留模型记忆风险，不将回放称为严格前瞻。当前没有 ForecastBench 自动抽样/清洗器、通用题库运行评分器或强对照实验；本入口不改变旧软件发布A/B/C实验。

## 体育与政治的小样本闭环

支持两个定性问题族：男子世界杯决赛是否进入加时、美国总统选举是否由上届总统选举获胜党继续获胜。前者先导为2014/2018/2022三个连续届次，后者为2008/2012/2016/2020四个连续周期。官方来源为UEFA、国家足协和美国国家档案馆。资料保存在data/domain-cases-pilot；CSV可供逐条查看，JSON保留来源摘录和哈希。完整抓取正文仅供本地审计，不随报告导出，不声明已获全文再发布许可。

```powershell
uv run --locked python scripts/prepare_domain_cases.py --output data/domain-cases-pilot/prepared-new-version
uv run --locked future-agent reference import-cases data/domain-cases-pilot/prepared-v1/sports.json
uv run --locked future-agent reference import-cases data/domain-cases-pilot/prepared-v1/politics.json
uv run --locked future-agent reference cases sports
uv run --locked future-agent reference cases politics
uv run --locked future-agent reference replay-input politics us-president-2016
```

prepare脚本只处理已经保存的官方来源捕获文件；不联网、不调用模型，不覆盖已有输出。新抓取必须另存捕获包并保留真实时间。当前源文件由TinyFish正文获取保存；本机StaticPageReader仍有unsafe_url限制，未绕过其安全检查。

设置HISTORICAL_REFERENCE_ENABLED=true后，普通chat和Web会在研究前和最终事件后查询同一参照服务。目标须明确为上述问题族并填写届次；不是任何体育/政治问题都能匹配。案例状态为qualitative_only，不提供观察概率、训练或自动校准。目标同届和截止时结果尚不可知的案例被排除，旧预测恢复固定原绑定。

replay-input是白名单历史事实重建输入，不提供目标结果、完整结果正文或实时搜索。其他已结局案例仅在结果可知界限早于目标题截止时进入参照。现时官方资料不能证明当时网页版本无后续编辑，因此仅作开发诊断；正常事前预测仍要求实际获取/入库早于当前截止。截止、窗口和结果可知界限均为显式UTC；保守上界不是最早公开时间。

程序核对（program_source_checked）不等于人工独立批准；不修改旧发布数据集的human门槛。事前字段目前很少，没有完整民调、球队状态等研究包；历史回放仍有模型记忆风险。
